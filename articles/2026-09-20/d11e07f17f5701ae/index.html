Server ActionsとRoute Handlers、「約束の性質」で選ぶ

体験談zenn.dev2026.09.20

Next.jsの実装者である筆者(ヒロ)が、実プロジェクト「SquadNote」での実装経験をもとに、Server ActionsとRoute Handlersのどちらを使うべきかを「呼び出し元との約束(契約)の性質」という観点から整理しています。検証にはVitest 4.1.4とNext.js 15.5.15が用いられています。

Server Actionsは画面で行った操作をサーバーへ渡す入口として位置づけられ、フォーム操作と画面遷移、認証処理と戻り先を統合的に管理する用途に向いているとされています。一方Route Handlersは、どのメソッドで呼び、何をヘッダーに付け、どの結果を受け取るかをHTTP仕様として明示化するもので、CronやモバイルアプリなどNext.js外部のクライアント向けに適するとしています。

記事はまた、フォームが存在するだけでは認可確認にはならないとセキュリティ上の注意を促しています。

出典が伝えている要点

  • 筆者はSquadNoteという実プロジェクトのコミット(0cda1e8)を例として取り上げている
  • 記事はVitest 4.1.4とNext.js 15.5.15を用いて検証を行っている
  • Server Actionsは画面で行った操作をサーバーへ渡す入口として位置づけられている
  • Server Actionsはフォーム操作と画面遷移をセットで扱う用途に向くとされている
  • Server Actionsは認証処理と戻り先を統合的に管理する用途に向くとされている
  • Route Handlersはどのメソッドで呼び、何をヘッダーに付け、どの結果を受け取るかをHTTP仕様として明示化する
  • Route HandlersはCronやモバイルアプリなど外部クライアント向けに適するとされている
  • Route HandlersはJSONレスポンスとHTTPステータスを正式な契約とする用途に向くとされている
  • 記事はフォームが存在するだけでは認可確認にはならないと警告している
