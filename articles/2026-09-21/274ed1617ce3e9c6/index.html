Claude Code連携、JevでコードレビューするPlugin

体験談zenn.dev2026.09.21

筆者のYusuke Kikuta(muse)氏が、Claude CodeのStop hook(作業完了時に発火する仕組み)に組み込んで使うプラグイン「jev-preflight」を開発しました。作業完了のタイミングでコード差分をJev APIに送って評価させ、セキュリティリスクが検出された場合のみ再調査を促す仕組みです。評価は「behavior regression」「authorization」「input validation」など8つのリスク軸で行われますが、Jev自身がバグを断定したり自動修正したりすることはなく、やるのは「もう一度だけ調べて」と促すところまでだといいます。

技術的な工夫として、EditイベントではなくStop時点で評価することで、Write操作やシェルコマンド経由の変更も含めた完全なターン差分を確認できる点、ユーザーの既存変更とClaudeの変更を分離するため実リポジトリに書き込まない別領域(プライベートGit tree)で差分を計算する点が挙げられています。Go言語採用によりmacOS/Linux/Windowsの計6環境へ単一バイナリで配布でき、API障害時も開発を止めないfail-open設計になっています。

利用にはClaude Code 2.1.257以降、Git、Bash、TypeSafe APIキーが必要です。既定の閾値0.85は未キャリブレーションで誤検知もあり得るとされており、セキュリティゲートではなく「終了前の振り返り支援ツール」として位置づけられています。

出典が伝えている要点

  • Yusuke Kikuta(muse)氏が「jev-preflight」というClaude Code用プラグインを開発した。
  • このプラグインはClaude CodeのStop hookに組み込んで使用する。
  • 作業完了時にコード差分をJev APIで評価し、セキュリティリスクが検出された場合のみ再調査を促す。
  • 評価は「behavior regression」「authorization」「input validation」「data integrity」「error handling」「compatibility」「lifecycle」「regression tests」の8つのリスク軸で行われる。
  • Jev自身はバグを断定したり自動修正したりはせず、「もう一度だけ調べて」と促すだけである。
  • EditイベントではなくStop時点で評価することで、Writeやシェルコマンド経由の変更も含めた完全なターン差分を確認できる。
  • ユーザーの既存変更とClaudeの変更を分離するため、実リポジトリのindex/refs/objectsに書き込まない別領域(プライベートGit tree)で差分を計算する。
  • Go言語を採用しており、ランタイム依存性がなくmacOS/Linux/Windowsの各32/64ビット計6環境へ単一バイナリで配布可能である。
  • API障害時も開発を止めず短いお知らせのみ表示するfail-open設計になっている。
  • セキュリティゲートではなく「終了前の振り返り支援ツール」として位置付けられている。
  • インストールには claude plugin marketplace add muse0509/jev-preflight と claude plugin install jev-preflight@jev-preflight を実行する。
  • 利用にはClaude Code 2.1.257以降、Git、Bash、TypeSafe APIキーが必要で、既定閾値0.85は未キャリブレーションであり誤検知もあり得るとされている。
