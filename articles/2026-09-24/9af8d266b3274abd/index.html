ORM選定に迷ったらPoEAAの設計パターンに立ち返る

報道zenn.dev2026.09.24

TypeScript案件でORM（Object-Relational Mapper）を選ぶ際、Martin FowlerのPoEAA（Patterns of Enterprise Application Architecture）で紹介されているデータアクセス設計パターンを判断基準にすべきだと提案する記事です。「なんとなく流行っているから」で選ぶと、後で「思っていたのと違う」となるリスクを指摘しています。

記事が挙げるのはActive Record、Data Mapper、Table Data Gateway、Row Data Gatewayの4パターン。エンティティ自身が操作用メソッドを持つActive RecordにはTypeORMとSequelizeが、ドメインモデルとデータアクセス処理を分離しDDD（ドメイン駆動設計）向きのData MapperにはMikroORMが該当するとしています。

型安全性を重視するTable Data GatewayにはPrismaとDrizzleが該当し、Row Data Gatewayは現代のORMではあまり採用されていないと述べています。

出典が伝えている要点

  • 記事はMartin FowlerのPoEAA(Patterns of Enterprise Application Architecture)で紹介されている設計パターンをORM技術選定の判断基準として提案している
  • 記事はデータアクセスに関するパターンとしてActive Record、Data Mapper、Table Data Gateway、Row Data Gatewayの4つを挙げている
  • Active Recordパターンはエンティティ自身が操作用メソッドを持つ設計だとしている
  • Active Recordパターンに該当するORMとしてTypeORMとSequelizeが挙げられている
  • Data Mapperパターンはドメインモデルとデータアクセス処理が分離された設計でDDD(ドメイン駆動設計)向きだとしている
  • Data Mapperパターンに該当するORMとしてMikroORMが挙げられている
  • Table Data Gatewayパターンは型安全性を重視する設計だとしている
  • Table Data Gatewayパターンに該当するツールとしてPrismaとDrizzleが挙げられている
  • Row Data Gatewayパターンは現代のORMではあまり採用されていないと記事は述べている
  • 筆者は記事末尾で、ORMを利用しているアプリケーションと利用していないアプリケーションの両方を業務で扱った経験があると述べている

原文より

「なんとなく流行っているから」で選んでみて後になって「思っていたのと違う」となるのは避けたいですね。ORMごとに設計思想が異なり、向いているユースケースも違います。
