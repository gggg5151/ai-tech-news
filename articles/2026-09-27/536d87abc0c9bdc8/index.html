AI感のないAWS構成図、5パターンで検証

体験談qiita.com2026.09.27

AIエージェントが生成するAWS構成図は「角が丸っぽい」「AI感がある」「線が重なる」など品質面の課題があると筆者は指摘します。そこでAWS Diagram MCP(Model Context Protocolの略、AIとツールをつなぐ共通規格)Server、aws-architecture-diagramスキル、draw.io MCP Tool Server、draw.io Claude Codeプラグイン、Claude Code単体の5パターンで同一の構成図を生成し、出力品質を比較検証しています。検証環境はClaude Code バージョン2.1.278、モデルはClaude Opus 5です。

線とラベルの重複回避、AWS公式アイコンの使用、アベイラビリティゾーンの正式名称記載、配置ルールの統一、線の出発点を辺の中央に指定するといった追加指示を組み込むことで、全パターンで品質が向上したとしています。特にdraw.io MCP、draw.io Claude Codeプラグイン、Claude Code単体の3パターンは「業務利用レベル」に達したと評価しています。

筆者は検証で使用した指示をまとめたカスタムスキルも公開しており、同じ課題を抱えるエンジニアがすぐに試せる形になっています。

出典が伝えている要点

  • 著者はAIエージェントが生成するAWS構成図について、角が丸っぽい・AI感がある・線が重なるなどの品質上の問題があると指摘している
  • 著者は5つのパターンで同じAWS構成図を生成して比較検証した
  • 検証に使用したツールはAWS Diagram MCP Server、aws-architecture-diagramスキル、draw.io MCP Tool Server、draw.io Claude Codeプラグイン、Claude Code単体の5つ
  • 検証環境はClaude Code バージョン2.1.278、使用モデルはClaude Opus 5
  • 起動オプション--strict-mcp-configで不要なMCPを除外して検証した
  • 著者は追加指示として線とラベルの重複回避、AWS公式アイコンの使用、アベイラビリティゾーンの正式名称記載、図要素の配置ルール統一、線の出発点を辺の中央に指定することを組み込んだ
  • 詳細で明確な指示を与えることで全パターンで品質が向上したと著者は述べている
  • draw.io MCP、draw.io Claude Codeプラグイン、Claude Code単体の3パターンが業務利用レベルに達したと著者は評価している
  • 著者は検証で使用した指示を集約したカスタムスキルを公開した
