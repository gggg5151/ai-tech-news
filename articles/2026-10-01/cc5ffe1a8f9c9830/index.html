wranglerから新CLI「cf」へ、移行の勘所

体験談zenn.dev2026.10.01

Cloudflareの新しいCLIツール「cf」（v1.0.0-beta）への移行方法を、個人開発者が実際に手を動かしながら解説した記事です。従来の「wrangler」から、cloudflare.config.tsベースの設定を使う新CLIへの切り替え手順を、React Router v8とViteを使ったプロジェクトを題材にまとめています。

移行は「pnpm dlx cf migrate」、型定義生成は「cf workers types」、デプロイは「cf deploy」の各コマンドで行い、Vite設定側では「experimental: { newConfig: true }」の指定が必要とのことです。Hyperdrive、R2、D1、Workers、Queueといった主要リソースを扱う手順にも触れています。

実務上の注意点として、Windows環境で「spawn EFTYPE」エラーが発生する問題や、「--var」オプションの廃止、移行後もwrangler.jsoncファイルを並行して維持する必要がある点が挙げられています。ベータ版らしい荒削りさが垣間見える内容です。

出典が伝えている要点

  • Cloudflareの新CLIツール「cf」のバージョンはv1.0.0-betaである
  • 記事は従来のCLIツール「wrangler」から「cf」への移行手順を解説している
  • 新CLIでは設定ファイルとして「cloudflare.config.ts」を使用する
  • 移行コマンドとして「pnpm dlx cf migrate」が使われる
  • 型定義生成には「cf workers types」コマンドを使う
  • デプロイには「cf deploy」コマンドを使う
  • Vite設定で「experimental: { newConfig: true }」を指定する必要がある
  • 記事はReact Router v8とViteを使ったプロジェクトを対象にしている
  • 言及されているCloudflareリソースにはHyperdrive、R2、D1、Workers、Queueが含まれる
  • Windows環境で「spawn EFTYPE」エラーが発生する問題が指摘されている
  • 新CLIでは「--var」オプションが廃止されたと記事は述べている
  • 移行後もwrangler.jsoncファイルを並行して維持する必要があると記事は述べている
