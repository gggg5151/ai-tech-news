APIキーの渡し方6種類、エージェント別に安全性を検証

報道qiita.com2026.10.06

Claude Code、Codex、Gemini CLI、GitHub Copilot、Cursorの各AIエージェントにAPIキーを渡す方法として、対話文に貼る、.envファイル、環境変数、MCP設定ファイルへの記載、OAuth認可、クラウド鍵置き場の6つを比較した記事です。対話文に貼る方法はキーがサーバーに送信され会話記録に残るため最も危険、.envもファイル読み取り拒否設定で部分的にしか防げないとされています。

各ツールの実際の挙動も細かく検証されています。Claude Codeは読み取り拒否規則があってもcatコマンドによる読み取りを遮断できる一方、環境変数は初期状態でAIに渡される挙動があるとのことです。Codexは初期設定で環境変数をすべて実行コマンドに渡しますが、shell_environment_policyという設定で渡す範囲を絞れます。Gemini CLIは.envファイルを自動的に読み込み、その挙動について設定の説明に矛盾がある点も指摘されています。GitHub CopilotのContent exclusion機能は、CLIやエージェントモードでの利用時には適用対象外になるとのことです。

OAuth認可はキー文字列そのものを渡さず有効期限や権限範囲を限定できるため「いちばん安全」と評価されています。一方でAstrix Securityの調査では、公開されているMCP（AIとツールを接続する標準プロトコル）サーバーのうち53%が有効期限の長い固定キーを使用し、OAuth対応はわずか8.5%にとどまるという現状も紹介されており、実務での見直しポイントが明確です。

出典が伝えている要点

  • 記事は、AIエージェントにAPIキーを渡す方法として6つを挙げている：対話文に貼る、.envファイルに記載、環境変数（.zshrc等）に設定、MCP設定ファイルに記載、OAuth認可、クラウド鍵置き場
  • 対話文にAPIキーを貼る方法は、キーがサーバーに送信され会話記録に残るため最も危険だと記事は述べている
  • .envファイルにAPIキーを記載する方法は、ファイル読み取り拒否設定を使っても部分的にしか防げないと記事は述べている
  • 環境変数（.zshrc等）にAPIキーを設定する方法は、AIからは見えないが、AIが実行するコマンドには環境変数が受け継がれると記事は述べている
  • MCP設定ファイルにAPIキーを記載する方法は、設定ファイルが漏洩した場合にキーも流出するため、環境変数を参照する形が推奨されると記事は述べている
  • OAuth認可による方法は、キー文字列そのものを渡さず、有効期限や権限範囲を限定できるため「いちばん安全」だと記事は評価している
  • Claude CodeとCodexは、クラウド鍵置き場を使う場合にキー文字列をAIに渡さない仕組みになっていると記事は述べている
  • Claude Codeは、読み取り拒否規則を設定していてもcatコマンドによる読み取りを遮断できる一方、環境変数は初期状態でAIに渡される挙動があると記事は述べている
  • Codexは初期設定で環境変数をすべて実行コマンドに渡し、shell_environment_policyという設定で渡す範囲を絞ることができると記事は述べている
  • Gemini CLIは.envファイルを自動的に読み込み、その挙動について設定の説明に矛盾がある点を記事は指摘している
  • GitHub CopilotのContent exclusion機能は、CLIやエージェントモードでの利用時には適用対象外になると記事は述べている
  • Astrix Securityの調査によれば、公開されているMCPサーバーのうち53%が有効期限の長い固定キーを使用しており、OAuthに対応しているのは8.5%にとどまると記事は紹介している
