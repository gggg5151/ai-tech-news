Claude Codeに.envや鍵ファイルを消させないフックを自作

体験談zenn.dev2026.10.18

筆者(Oskra)はClaude Codeに作業を任せる際、確認プロンプトの多さに困り「確認なしで実行」設定を使っていたところ、AIが.envや.p8、.pemなどの鍵ファイルを誤って削除・移動するリスクに気づきました。特にApp Store Connectの鍵は1回しかダウンロードできず、消されると作り直しと利用箇所の全差し替えが必要になります。

これを防ぐため、Claude CodeのPreToolUse(ツール実行前に呼ばれるフック)として動くNode.jsスクリプト(~/.claude/hooks/secret-guard-mini.mjs、111行)を自作しました。コマンド実行前に引数のファイルパスを絶対パスに正規化し、鍵ファイルや.env関連ファイルへのrm/mv/cp/curl @等の危険操作を検出して終了コード2でブロックします。「"matcher": "Bash" は、Bashのコマンドのときだけ走らせる指定です」とし、settings.jsonに記述すれば全プロジェクトで有効になります。

deny(拒否ルール)のみの場合、危険な11パターンのコマンドのうち9通りをブロックできましたが、/bin/rmやpython3 -cによる削除は防げませんでした。deny+hook併用では10通りまでブロック数が増えましたが、python3 -c "import os; os.remove('.env')"のようなスクリプト経由の削除は依然防げず、著者はsandboxでの対応が必要だと述べています。検証環境はClaude Code 2.1.302、Node.js 22.22.2、Ubuntu 24.04(WSL2)です。

出典が伝えている要点

  • 著者はClaude Codeの確認プロンプトの多さに困っていたが「確認なしで実行」設定を使用していた
  • その設定によりAIが.envや.p8、.pemなどの鍵ファイルを誤って削除する危険があった
  • App Store Connectの鍵は1回しかダウンロードできなく、消されると作り直しと全差し替えが必要になる
  • 著者は~/.claude/hooks/secret-guard-mini.mjsという111行のNode.jsスクリプトを作成した
  • このhookはClaude CodeのPreToolUseのタイミングで実行前のコマンド全文と現在ディレクトリを受け取る
  • hookは引数のファイルパスを絶対パスに変換してから検査し、鍵ファイルや.env関連ファイルへのrm/mv/cp/curl @コマンドを終了コード2でブロックする
  • 設定は~/.claude/settings.jsonのhooksに記述し、"matcher": "Bash"でBashコマンド実行時のみ動作するよう指定する
  • denyルールのみの場合、危険な11通りのコマンドのうち9通りをブロックでき、/bin/rmとpython3 -cによる削除はブロックされなかった
  • deny+hookを併用した場合、11通りのうち10通りをブロックでき、/bin/rmはブロックされるようになった
  • python3 -c "import os; os.remove('.env')"のようなスクリプト経由の削除は依然ブロックできず、著者はsandboxでの対応が必要と述べている
  • 検証環境はClaude Code 2.1.302、Node.js 22.22.2、Ubuntu 24.04(WSL2)である

原文より

"matcher": "Bash" は、Bash のコマンドのときだけ走らせる指定です。
~/.claude/settings.json に、次の hooks を足します。ここに書くと、すべてのプロジェクトで効きます。
