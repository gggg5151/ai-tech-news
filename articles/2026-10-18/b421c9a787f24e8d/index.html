Next.js 14→15、fetchキャッシュのデフォルト反転に注意

体験談qiita.com2026.10.18

Next.js 14から15へのバージョンアップで発生したfetchキャッシュの挙動変更について、筆者(Cosoado)が自身のプロジェクト「NetaPair」で実際に直面した問題をもとに解説しています。v14まではキャッシュオプションを明示指定しなくてもforce-cache相当(キャッシュあり)として動いていたfetchのデフォルト挙動が、v15ではno-store相当(キャッシュなし)に反転した点が核心です。

移行チェックリストとして、認証済みユーザーの動的データなど毎回フレッシュに取得したい場合はcache: 'no-store'、定期更新が必要な場合はnext: { revalidate: 60 }、ビルド時に固定したい静的データはcache: 'force-cache'、ページ全体を動的化したい場合はexport const dynamic = 'force-dynamic'を使うべきとしています。

筆者はno-cacheとno-storeを混同して実装ミスをした経験があるとし、「毎回最新を取る」場合は必ずno-storeを使うべきだと強調しています。

出典が伝えている要点

  • 記事はNext.js 14から15へのバージョンアップに伴うfetchキャッシュの破壊的変更を扱っている

  • Next.js v14まではfetchにキャッシュオプションを明示的に指定しなくてもforce-cache相当として機能していた
