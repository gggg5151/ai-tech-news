E2Eテストのフィードバックループを縮める4つの工夫

体験談future-architect.github.io2026.10.18

フューチャー株式会社の技術ブログで、筆者の武田大輝氏が実際のプロジェクト経験(簡略化して紹介)に基づき、E2Eテスト(画面操作を通した通し試験)の「フィードバックループを小さくする」ための4つのプラクティスを解説しています。「コーディングエージェントやPlaywrightなどのテスト自動化ツールの登場で、E2Eテストの実装にかかる時間は劇的に短くなりました」とした上で、実行・デバッグのループを短縮する工夫が重要という立場です。

1つ目はデプロイレスでのテスト実行で、Docker Composeでローカルにクラウド環境と同じ構成(Keycloak、mailpit、Jaegerなど)を再現し、AWSエミュレーションにはLocalStackの有償化を受けてMiniStackを使用しています。テストは開発時・PR時・日次の3タイミングで実行されます。

2つ目はPlaywrightのworkersとfullyParallel設定によるテストの並列化で、GitHub Actionsの4コアランナーで約160件のテストを約13分で実行できたとしています。3つ目は画面キャプチャや操作記録に加えデータベースレコードとコンテナログを含む自己完結型のテストレポート、4つ目はトレースIDをPlaywrightが採番しtraceparentヘッダで伝播させる分散トレーシングで、失敗原因の特定を迅速化しています。

出典が伝えている要点

  • 記事の筆者は武田大輝氏であり、フューチャー株式会社の技術ブログに掲載されている
  • 記事は実際の現場で取り扱ったシステムを簡略化した例を用いて解説している
  • 記事はE2Eテストのフィードバックループを小さくするための4つのプラクティス（デプロイレスのテスト実行、テストの並列化、自己完結型のテストレポート、分散トレーシング）を紹介している
  • デプロイレスのテスト実行ではDocker Composeでローカル環境にクラウド環境と同じ構成を再現し、AWSエミュレーションにはLocalStackの有償化対応としてMiniStackを使用している
  • ローカル環境構成にはKeycloak、mailpit、Jaegerが含まれ、環境変数で接続先を切り替えている
  • テストは開発時（機能ブランチでコーディングエージェントが実行）、PR時（GitHub Actionsランナーで実行）、日次（クラウド環境で実行）の3タイミングで行われる
  • テストの並列化にはPlaywrightのworkersとfullyParallel設定を使用し、各テストは前処理でユーザーを作成、後処理で削除する
  • GitHub Actionsの4コアのランナーで約160件のテストを約13分で実行できたと記載されている
  • 自己完結型のテストレポートにはPlaywright標準の実行結果・画面キャプチャ・画面動画・操作記録に加え、カスタムレポーターでデータベースレコードとコンテナのログを含めている
  • 分散トレーシングのトレースIDを用いてログを検索する手法を使っている
  • 分散トレーシングはローカル環境でJaeger、クラウド環境でAWS X-Ray（CloudWatch Transaction Search/OTLP）を使用し、ログ集約にはローカルでVector、クラウドでCloudWatch Logsを使用している
  • トレースIDはPlaywrightが採番し、traceparentヘッダで複数サービス間に伝播させている

原文より

コーディングエージェントや Playwright などのテスト自動化ツールの登場で、E2E テストの実装にかかる時間は劇的に短くなりました。
