AIエージェントに.envを消させないためのhook自作記録

体験談qiita.com2026.10.19

Stack Overflowの調査では、仕事でAIエージェントを使う開発者の割合が2025年の31%から2026年4月には59%に増加したとされ、GitGuardianの報告でも公開GitHub上のシークレット（秘密情報）発見数が前年比34%増の約2,865万件に達したといいます。筆者はClaude Codeによる.envや鍵ファイルの誤削除・外部送信を防ぐため、denyルールだけの効果を検証したところ、危険な11コマンドのうち9通りしか防げなかったと報告しています。

そこで筆者が自作した111行のNode.js製hookを導入すると、11コマンド中10通りまで防げるようになりました。ただしpython3 -c経由でスクリプトを実行するコマンドはhookを通過してしまい、逆にrm .env.exampleのような無害な操作を止めてしまう誤検知も2件発生したとのことです。筆者は「書き方を追うかぎり漏れは残るので、最後の壁はsandboxにします」と今後の方針を述べています。

出典が伝えている要点

  • Stack Overflow調査によると、AIエージェントを仕事で使用する開発者の割合は2025年に31%、2026年4月に59%だった
  • GitGuardianの報告によると、2025年に公開GitHub上で約2,865万件の秘密情報（シークレット）が発見され、前年比34%増加した
  • Replit CEOが2025年7月に本番データ削除を認めたと記事は述べている
  • Claude CodeのGitHub issue #65034および#92542で.env削除の報告があったと記事は述べている
  • 筆者はClaude Code 2.1.302、Node.js 22.22.2、WSL2上のUbuntu 24.04の環境で検証した
  • denyルール単独では危険な11コマンドのうち9通りを防げたと記事は述べている
  • 筆者が追加した自作hook（111行のNode.jsプログラム）を導入すると、11コマンド中10通りを止められたと記事は述べている
  • python3 -cを使ったスクリプト経由のコマンドはhookを通過してしまうと記事は述べている
  • rm .env.exampleなど、意図しない誤検知（止めすぎ）が2通り発生したと記事は述べている

原文より

書き方を追うかぎり漏れは残るので、最後の壁はsandboxにします
