caddyserver/caddy の modules/caddyhttp/ip_range.go を読む

GitHub で実物を見る ↗2026.09.23

Caddyはミドルウェアを自作できるほど拡張性が高いGo製Webサーバーで、実運用されるOSSとしてコード品質が高いことで知られています。今日読むip_range.goは「アクセス元IPがCIDR範囲に含まれるか」を判定するための仕組みの一部。設定ファイルに書かれた"192.168.0.0/24"のような文字列を、Goの型安全なIPアドレス表現に変換する処理は、Web開発の実務で頻出するパターンなので教材に選びました。

コード

func (s *StaticIPRange) Provision(ctx caddy.Context) error {
	for _, str := range s.Ranges {
		prefix, err := CIDRExpressionToPrefix(str)
		if err != nil {
			return err
		}
		s.ranges = append(s.ranges, prefix)
	}

	return nil
}

// CIDRExpressionToPrefix takes a string which could be either a
// CIDR expression or a single IP address, and returns a netip.Prefix.
func CIDRExpressionToPrefix(expr string) (netip.Prefix, error) {
	// Having a slash means it should be a CIDR expression
	if strings.Contains(expr, "/") {
		prefix, err := netip.ParsePrefix(expr)
		if err != nil {
			return netip.Prefix{}, fmt.Errorf("parsing CIDR expression: '%s': %v", expr, err)
		}
		return prefix, nil
	}

	// Otherwise it's likely a single IP address
	parsed, err := netip.ParseAddr(expr)
	if err != nil {
		return netip.Prefix{}, fmt.Errorf("invalid IP address: '%s': %v", expr, err)
	}
	prefix := netip.PrefixFrom(parsed, parsed.BitLen())
	return prefix, nil
}

引用はリポジトリの実物と機械で照合しています。「// …略…」は省略した行です。

上から順に読む

func (s *StaticIPRange) Provision(ctx caddy.Context) error {

メソッドの定義です。`func (s *StaticIPRange)` の部分は「レシーバ」と呼ばれ、`StaticIPRange`という構造体に紐づくメソッドであることを示します。`*StaticIPRange`の`*`はポインタ型という意味で、「このメソッドは構造体のコピーではなく実体そのものを操作する（書き換えられる）」ことを示しています。戻り値の`error`はGoの標準的なエラー型です。

for _, str := range s.Ranges {

`range`はスライス（可変長配列）やmapを1要素ずつ取り出すループ構文です。`range s.Ranges`は「インデックス, 値」の2つを返しますが、ここではインデックスを使わないので`_`（ブランク識別子。値を捨てる時に使う）を置き、値だけを`str`という変数名で受け取っています。`:=`は「新しい変数を宣言しつつ代入する」短縮記法です。

prefix, err := CIDRExpressionToPrefix(str)

Goの関数は複数の値を同時に返せます。この行はその代表例で、変換結果の`prefix`と、失敗したかどうかを表す`err`を一度に受け取っています。呼び出す`CIDRExpressionToPrefix`は後ろで定義されている関数で、文字列をIPアドレスの範囲表現に変換します。

if err != nil {
			return err
		}

Goには例外機構（try/catch）がなく、エラーは戻り値として渡されます。そのため「関数を呼んだ直後にerrがnil（何もない状態）でないかチェックし、あればすぐreturnして呼び出し元に伝える」というこのパターンが、Goコードの至るところに現れます。慣れないうちは冗長に見えますが、これがGoの標準的な書き方です。

s.ranges = append(s.ranges, prefix)

`append`はスライスに要素を追加する組み込み関数です。スライスは固定長ではないので、`append`は必要なら内部でより大きな配列を確保し直します。`s.ranges = append(...)`のように必ず戻り値を元の変数に代入し直す点がポイントです（append自体は元のスライスを直接変更しない場合があるため）。

func CIDRExpressionToPrefix(expr string) (netip.Prefix, error) {

こちらは構造体に紐づかない普通の関数です。引数`expr string`は「exprという名前の、string型の引数」という意味（Goは型を変数名の後ろに書きます）。戻り値の`(netip.Prefix, error)`のようにカッコで複数の型を並べると、複数の値を返す関数だと宣言できます。`netip.Prefix`はGo標準ライブラリの`net/netip`パッケージが提供する、CIDR表記（IPアドレス＋ビット長）を表す型です。

if strings.Contains(expr, "/") {

`strings`パッケージの`Contains`関数で、文字列に`/`が含まれるかを判定しています。`192.168.0.0/24`のようなCIDR表記にはスラッシュがあり、単なる`192.168.0.1`のような単一IPにはないので、この有無で処理を分岐させています。

prefix, err := netip.ParsePrefix(expr)

`netip.ParsePrefix`は標準ライブラリの関数で、`"192.168.0.0/24"`のような文字列を解析して`netip.Prefix`型の値に変換します。文字列を自作でパースせず、標準ライブラリの型安全な関数に任せているのは、実務でよく見る「車輪の再発明をしない」判断です。

return netip.Prefix{}, fmt.Errorf("parsing CIDR expression: '%s': %v", expr, err)

`netip.Prefix{}`はその型の「ゼロ値」（何も入っていない空の状態）を作るリテラルです。エラー時は意味のある値がないので空の構造体を返しています。`fmt.Errorf`は`%s`や`%v`のようなプレースホルダーに値を埋め込んで新しいエラーを作る関数で、`%v`は元のエラー`err`をそのまま文字列化して埋め込み、「どの入力が」「元々どんなエラーだったか」の両方を保持したメッセージを作っています。

parsed, err := netip.ParseAddr(expr)

スラッシュがない場合（単一IPアドレスの場合）の分岐です。今度は`netip.ParseAddr`で単なるIPアドレス文字列（例: "192.168.0.1"）をパースしています。関数名の違い（ParsePrefix vs ParseAddr）から、標準ライブラリがCIDR用とアドレス単体用で型・関数を使い分けていることが読み取れます。

prefix := netip.PrefixFrom(parsed, parsed.BitLen())

単一IPアドレスを「範囲が自分自身だけのCIDR」として扱うための変換です。`parsed.BitLen()`はそのIPアドレスの全ビット数（IPv4なら32、IPv6なら128）を返すメソッドで、それをそのままプレフィックス長として使うことで「このIP1つだけを指す範囲」を表現しています。単一IPとCIDR範囲を同じ`netip.Prefix`型で統一的に扱えるようにする、地味だが実用的なテクニックです。

今日覚えて帰ること

Goでは「値, err := 関数呼び出し」の直後に「if err != nil { return err }」を書くのが基本パターン。例外機構がない代わりにこの形を徹底することで、エラーの発生源と伝播経路がコードを読むだけで追えるようになります。
