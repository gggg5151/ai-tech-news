docker/compose の internal/paths/paths.go を読む

GitHub で実物を見る ↗2026.09.25

docker/composeは、あの`docker compose up`コマンドを実装しているCLIツールです。このファイルはファイルパスを扱うユーティリティで、「あるパスが別のパスの子（配下）にあるかどうか」を判定する`IsChild`関数を持っています。単純に見える処理ですが、大文字小文字を区別するOS/しないOSが混在する現実に対応するための工夫があり、Goらしいエラーハンドリングと早期returnの書き方がまとまって学べるので選びました。

コード

func IsChild(dir string, file string) bool {
	if dir == "" {
		return false
	}

	dir = filepath.Clean(dir)
	current := filepath.Clean(file)
	child := "."
	for {
		if strings.EqualFold(dir, current) {
			// If the two paths are exactly equal, then they must be the same.
			if dir == current {
				return true
			}

			// If the two paths are equal under case-folding, but not exactly equal,
			// then the only way to check if they're truly "equal" is to check
			// to see if we're on a case-insensitive file system.
			//
			// This is a notoriously tricky problem. See how dep solves it here:
			// https://github.com/golang/dep/blob/v0.5.4/internal/fs/fs.go#L33
			//
			// because you can mount case-sensitive filesystems onto case-insensitive
			// file-systems, and vice versa :scream:
			//
			// We want to do as much of this check as possible with strings-only
			// (to avoid a file system read and error handling), so we only
			// do this check if we have no other choice.
			dirInfo, err := os.Stat(dir)
			if err != nil {
				return false
			}

			currentInfo, err := os.Stat(current)
			if err != nil {
				return false
			}

			if !os.SameFile(dirInfo, currentInfo) {
				return false
			}
			return true
		}

		if len(current) <= len(dir) || current == "." {
			return false
		}

		cDir := filepath.Dir(current)
		cBase := filepath.Base(current)
		child = filepath.Join(cBase, child)
		current = cDir
	}
}

引用はリポジトリの実物と機械で照合しています。「// …略…」は省略した行です。

上から順に読む

func IsChild(dir string, file string) bool {

funcは関数を定義するキーワード。IsChildが関数名、続く丸括弧の中身(dir string, file string)が引数リストで、両方ともstring型。丸括弧の外側にあるboolが戻り値の型で、Goでは戻り値の型を引数リストの後ろに書く。この関数は「fileがdirの配下（子）にあるか」をtrue/falseで返す。

if dir == "" {
		return false
	}

早期return（ガード節）と呼ばれる書き方。dirが空文字列なら、その後の処理を続けても意味がないので、関数の先頭ですぐfalseを返して抜けてしまう。Goには例外機構がなく、こうして「まず異常系・自明なケースを弾いてから本処理を書く」パターンが多用される。

dir = filepath.Clean(dir)
	current := filepath.Clean(file)

filepath.Cleanはパスを正規化する標準ライブラリの関数で、例えば"/foo/./bar/../baz"を"/foo/baz"のように整理する。dirは既存の引数への再代入なので`=`、currentは新しい変数を宣言すると同時に代入するので`:=`（短縮変数宣言）を使っている。この`=`と`:=`の使い分けはGoの基本ルール。

child := "."

ループの中で使う作業用の文字列変数をここで宣言している。初期値の"."は「カレントディレクトリ」を表す一般的な表記。

for {

Goのforは条件式を書かずに`for {}`とだけ書くと無限ループになる（他言語のwhile(true)と同じ）。ループから抜けるにはbreakかreturnが必要で、この関数では内部の複数のreturn文だけでループを抜ける設計になっている。

if strings.EqualFold(dir, current) {

strings.EqualFoldは大文字小文字の違いを無視して2つの文字列を比較する関数。例えば"ABC"と"abc"はtrueになる。ここではdirとcurrentが「大文字小文字を無視すれば」一致するかどうかを最初にチェックしている。

if dir == current {
				return true
			}

EqualFoldで一致した上で、さらに`==`（厳密な完全一致、大文字小文字も区別する）で比較している。両方とも一致するなら文字列として完全に同じパスなので、迷わずtrueを返して関数を終える。

// This is a notoriously tricky problem. See how dep solves it here:
			// https://github.com/golang/dep/blob/v0.5.4/internal/fs/fs.go#L33

EqualFoldでは一致するのに`==`では一致しない＝大文字小文字だけが違うケースが起きたとき、それが本当に同じファイルかどうかはOSのファイルシステムが大文字小文字を区別するか（macOSやWindowsは基本区別しない、Linuxは区別する）に依存する。コード側は文字列だけでは判断できないと認めた上で、次の行から実際のファイルシステムに問い合わせて確認しに行く。

dirInfo, err := os.Stat(dir)
			if err != nil {
				return false
			}

os.Statはファイルやディレクトリのメタ情報（os.FileInfo型）を取得する標準ライブラリ関数。Goの多くの関数は(結果, error)の2つの値を返す設計になっており、呼び出し側はerrがnilでないかを毎回チェックする。ここでもStatに失敗したら（例えばパスが存在しない）、安全側に倒してfalseを返している。

if !os.SameFile(dirInfo, currentInfo) {
				return false
			}
			return true

os.SameFileは2つのFileInfoが実際に同一のファイル（同じinodeなど）を指しているかを判定する関数。先頭の`!`は否定演算子で、「同じファイルでない」場合にfalseを返し、それ以外（同じファイルだった）場合はtrueを返す。文字列だけでは決められなかった「大文字小文字違いだが実は同じファイルかもしれない」問題を、最終的にOSレベルの情報で決着させている。

if len(current) <= len(dir) || current == "." {
			return false
		}

ループを終了させるもう一つの条件。lenは文字列の長さ（バイト数）を返す組み込み関数。currentを親ディレクトリへ遡っていった結果、dirと同じかそれより短くなった、あるいはルートまで遡り切って"."になった場合は、もう一致する見込みがないのでfalseを返す。`||`は論理OR（どちらか一方でも真なら成立）。

cDir := filepath.Dir(current)
		cBase := filepath.Base(current)
		child = filepath.Join(cBase, child)
		current = cDir

filepath.Dirはパスから最後の要素を除いた「親ディレクトリ」部分を返し、filepath.Baseは逆に最後の要素だけを返す標準ライブラリ関数。例えば"/foo/bar/baz"ならDirは"/foo/bar"、Baseは"baz"になる。ここでcurrentを1階層ずつ親に向かって書き換えながらループの先頭（strings.EqualFoldでの比較）に戻ることで、ディレクトリツリーを下から上へ1段ずつ歩いてdirと一致するか確認していく。

今日覚えて帰ること

Goでは`結果, err := 何かの関数()`のあと必ず`if err != nil { return ... }`で即座に異常系を片付けてから次の処理に進む、というガード節スタイルの一貫性を意識すると、実務コードがぐっと読みやすくなる。
