go-playground/validator の cache.go を読む

GitHub で実物を見る ↗2026.09.29

go-playground/validatorはGoの構造体タグ(`validate:"required,email"`のような書き方)でバリデーションを行う定番ライブラリです。構造体のタグ解析は文字列処理を含むためそこそこ重く、同じ型を毎回リクエストごとに解析すると遅くなります。そこで「一度解析した結果をキャッシュしておく」ためのstructCache/tagCacheという仕組みがcache.goにあります。ここには「読み取りは頻繁・書き込みはまれ」というWebサーバー特有のアクセスパターンに対して、Goの並行処理プリミティブをどう使うかという実践的な設計判断が詰まっているので選びました。

コード

type structCache struct {
	lock sync.Mutex
	m    atomic.Value // map[reflect.Type]*cStruct
}

func (sc *structCache) Get(key reflect.Type) (c *cStruct, found bool) {
	c, found = sc.m.Load().(map[reflect.Type]*cStruct)[key]
	return
}

func (sc *structCache) Set(key reflect.Type, value *cStruct) {
	m := sc.m.Load().(map[reflect.Type]*cStruct)
	nm := make(map[reflect.Type]*cStruct, len(m)+1)
	for k, v := range m {
		nm[k] = v
	}
	nm[key] = value
	sc.m.Store(nm)
}

type tagCache struct {
	lock sync.Mutex
	m    atomic.Value // map[string]*cTag
}

func (tc *tagCache) Get(key string) (c *cTag, found bool) {
	c, found = tc.m.Load().(map[string]*cTag)[key]
	return
}

func (tc *tagCache) Set(key string, value *cTag) {
	m := tc.m.Load().(map[string]*cTag)
	nm := make(map[string]*cTag, len(m)+1)
	for k, v := range m {
		nm[k] = v
	}
	nm[key] = value
	tc.m.Store(nm)
}

引用はリポジトリの実物と機械で照合しています。「// …略…」は省略した行です。

上から順に読む

type structCache struct {
	lock sync.Mutex
	m    atomic.Value // map[reflect.Type]*cStruct
}

structという構造体を定義しています。`type 名前 struct { フィールド... }`はGoの構造体定義の基本形です。フィールドは2つ。`lock sync.Mutex`は排他ロック(ミューテックス)で、「同時に1つのゴルーチン(Goの軽量スレッド)しかこの値を触れないようにする」ための道具です。`m atomic.Value`は「読み書きをアトミック(不可分)に行える箱」で、複数のゴルーチンが同時にLoad(読む)・Store(書く)しても壊れないことが保証されています。コメント`// map[reflect.Type]*cStruct`はコンパイラには効きませんが、「このValueの中には実際にはこの型のmapが入っている」という約束をコードを読む人に伝えるためのものです。atomic.Valueはinterface{}(任意の型)を保持するので、型情報がコード上からは見えなくなるのを、この一行コメントで補っています。

func (sc *structCache) Get(key reflect.Type) (c *cStruct, found bool) {

メソッド定義です。`func (sc *structCache) Get(...)`の`(sc *structCache)`部分は「レシーバ」で、この関数を`structCache`型の値(のポインタ)に対する専用メソッドにします。呼び出すときは`sc.Get(key)`のように書けます。`*structCache`とポインタ型にしているのは、値をコピーせず元の構造体を直接操作・参照したいからです。戻り値の`(c *cStruct, found bool)`は「名前付き戻り値」で、関数の中で`c`と`found`という名前の変数がすでに用意されている状態で処理が始まります(この後の行で使われます)。

c, found = sc.m.Load().(map[reflect.Type]*cStruct)[key]

1行にいくつもの処理が詰まっています。まず`sc.m.Load()`でatomic.Valueに今入っている値を安全に取り出します。返り値の型は`interface{}`(なんでも入る型)なので、次に`.(map[reflect.Type]*cStruct)`という「型アサーション」でそれを目的のmap型に変換します。最後に`[key]`でそのmapからkeyに対応する値を取り出します。Goのmapは`値, ok := m[key]`という書き方(コンマok構文)ができ、keyが存在しない場合は`ok`がfalseになり、値はゼロ値(この場合はnil)になります。ここではその2つの受け皿として、前の行で用意されていた名前付き戻り値`c`と`found`にそのまま代入しています。

return
}

引数も値もない、ただの`return`です。これができるのは戻り値がすでに名前付き(`c *cStruct, found bool`)で宣言されているためで、Goでは「名前付き戻り値」に値を入れておけば、最後に`return`と書くだけでその時点の値がそのまま返されます。何を返しているか一目で分かりにくくなる面もありますが、短いGetterではよく使われる書き方です。

func (sc *structCache) Set(key reflect.Type, value *cStruct) {
	m := sc.m.Load().(map[reflect.Type]*cStruct)

Setメソッドの中身です。まず現在atomic.Valueに入っているmapを、Getと同じ手順(Load→型アサーション)で取り出し、ローカル変数`m`に入れます。`:=`はGoの短縮変数宣言で、「新しい変数`m`を作り、右辺の値で初期化する」という意味です。ここではまだ何も変更しておらず、あくまで「今の状態のスナップショットを読んだ」だけです。

nm := make(map[reflect.Type]*cStruct, len(m)+1)
	for k, v := range m {
		nm[k] = v
	}

`make(map[K]V, n)`はmapを新しく作る組み込み関数で、第2引数は「これくらいの要素数が入る予定です」という容量のヒントです(厳密な上限ではなく、内部の再確保を減らすための最適化)。ここでは元のmapの要素数+1(これから1件追加するため)を渡しています。続く`for k, v := range m { ... }`は「mapのすべてのキーと値を順番に取り出すループ」で、Goのmapを全走査する標準的な書き方です。ループの中で、古いmap`m`の内容をすべて新しいmap`nm`にコピーしています。つまり、既存のmapを直接書き換えるのではなく、コピーした新しいmapを作っているのがポイントです。

nm[key] = value
	sc.m.Store(nm)
}

コピーしてできた新しいmap`nm`に、今回追加したいkeyとvalueを書き込みます。そして最後に`sc.m.Store(nm)`で、atomic.Value全体を新しいmapに丸ごと入れ替えます。ここが重要な設計です。Storeは一瞬で完了する「差し替え」の操作なので、他のゴルーチンがちょうどそのタイミングでLoad()していても、古い完全なmapか新しい完全なmapのどちらかしか見えません。作業途中の中途半端なmapが見えることは絶対にないので、Get側でロックを取らなくても安全に読めるのです。

type tagCache struct {
	lock sync.Mutex
	m    atomic.Value // map[string]*cTag
}

同じ構造がもう一度出てきます。今度はキーが`reflect.Type`ではなく`string`(タグ文字列)で、値も`*cStruct`ではなく`*cTag`です。GetとSetの実装ロジックはstructCacheと一字一句同じパターンで、型だけが違います。このコードが書かれた時点のGoにはジェネリクス(型を後から差し込める仕組み)がまだ普及していなかったため、同じロジックを型ごとに手で書き直す必要がありました。今のGoであれば`type cache[K comparable, V any] struct {...}`のような形で1つにまとめられますが、ここでは意図的に(あるいは歴史的経緯で)コピー＆ペーストされています。

今日覚えて帰ること

「読み取りが多く書き込みがまれ」なキャッシュは、mutexでmap全体をロックするより、atomic.ValueにイミュータブルなmapをStoreで丸ごと差し替える方式にすると、読み取り側が一切ロックを待たずに安全に動くようになる。
