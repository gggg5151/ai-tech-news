urfave/cli の flag_bool.go を読む

GitHub で実物を見る ↗2026.10.01

urfave/cliはGoでコマンドラインツールを作るための定番ライブラリで、GitHub上で2万を超えるスターを集めています。flag_bool.goは「真偽値(true/false)を受け取るフラグ」を実装しているファイルです。ファイル全体は約75行と短く、しかも標準ライブラリのflag.Value interfaceを実装するという一つの目的に絞られているため、Goのポインタ・interface・エラー処理という基本イディオムを一度に確認できる、新卒1年目にちょうど良い教材だと判断しました。

コード

package cli

import (
	"errors"
	"strconv"
)

// …略…

// boolValue needs to implement the boolFlag internal interface in flag
// to be able to capture bool fields and values
//
//	type boolFlag interface {
//		  Value
//		  IsBoolFlag() bool
//	}
type boolValue struct {
	destination *bool
	count       *int
}

// …略…

// Below functions are to satisfy the flag.Value interface

func (b *boolValue) Set(s string) error {
	v, err := strconv.ParseBool(s)
	if err != nil {
		err = errors.New("parse error")
		return err
	}
	*b.destination = v
	if b.count != nil {
		*b.count = *b.count + 1
	}
	return err
}

func (b *boolValue) Get() any { return *b.destination }

func (b *boolValue) String() string {
	return strconv.FormatBool(*b.destination)
}

func (b *boolValue) IsBoolFlag() bool { return true }

引用はリポジトリの実物と機械で照合しています。「// …略…」は省略した行です。

上から順に読む

import (
	"errors"
	"strconv"
)

importは他のパッケージをこのファイルで使えるようにする宣言です。errorsはエラー値を作るための標準パッケージ、strconvは「文字列⇔数値/真偽値」の変換を行う標準パッケージです。カッコでまとめて複数importするのはGoの定番の書き方です。

type boolValue struct {
	destination *bool
	count       *int
}

structは複数のフィールドをまとめる型です。ここでは*boolと*intという「ポインタ型」のフィールドを持っています。*T は「T型の値が置かれているメモリ上の場所（アドレス）」を表す型です。destinationは呼び出し元が持っているbool変数そのものを指し、countはそのフラグが何回指定されたかを数えるint変数を指します。ポインタを持つことで、boolValue側からその変数の値を直接書き換えられます。

// boolValue needs to implement the boolFlag internal interface in flag

これはコメント（// で始まる行）で、コードの実行には関係ありませんが「なぜこの型が存在するのか」を説明しています。Goのinterfaceは「このメソッド群を持っていれば自動的にそのinterfaceを満たしたことになる」という暗黙的な仕組みです。つまりboolValueは『boolFlagです』と明示的に宣言する必要はなく、必要なメソッド（Value相当のメソッド＋IsBoolFlag()）を実装しさえすればflag.Value（boolFlag）として扱われます。

func (b *boolValue) Set(s string) error {

これはメソッド定義です。func の後の (b *boolValue) が「レシーバ」で、このメソッドは*boolValue型（boolValueのポインタ）に対して呼び出せることを意味します。ポインタレシーバを使う理由は、メソッド内でbの中身（destinationが指す値など）を書き換えたいからです。値レシーバだとコピーに対する変更になり、呼び出し元には反映されません。引数s stringを受け取り、戻り値としてerror型を返します。

v, err := strconv.ParseBool(s)
	if err != nil {
		err = errors.New("parse error")
		return err
	}

strconv.ParseBool(s)は文字列s（例: "true"や"1"）をbool値に変換しようとします。関数は(戻り値, エラー)の2つを返すのがGoの定番パターンで、v, err := ... で両方を新しい変数として受け取ります（:=は「型を書かずに宣言して代入」する記法）。if err != nil は「エラーが発生していたら」という判定です。ここでは元のエラー内容を捨てて、errors.New("parse error")というシンプルな新しいエラーを作り直して返しています。

*b.destination = v
	if b.count != nil {
		*b.count = *b.count + 1
	}

変換に成功した場合の処理です。*b.destination はポインタの前に*を付けて「そのポインタが指している先の値そのもの」を表します（これを「デリファレンス」と呼びます）。*b.destination = v で、呼び出し元のbool変数に新しい値vを書き込みます。続くif文はcountポインタがnil（何も指していない）でなければ、その指し先の値を1増やします。これで「-v -v -v」のように同じフラグを複数回指定した回数を数えられます。

func (b *boolValue) Get() any { return *b.destination }

anyはinterface{}の別名（Go1.18以降のエイリアス）で、「どんな型の値でも入れられる箱」を意味します。Get()はdestinationが指している現在のbool値を取り出して返すだけの、1行で書かれた短いメソッドです。波括弧を改行せず1行に書くのも短いメソッドでよく見るスタイルです。

func (b *boolValue) String() string {
	return strconv.FormatBool(*b.destination)
}

strconv.FormatBoolはParseBoolの逆で、bool値を"true"/"false"という文字列に変換します。このStringメソッドを持つ型はfmt.Stringer interfaceも同時に満たすことになり、Printlnなどで自動的にこの文字列表現が使われるようになります。

func (b *boolValue) IsBoolFlag() bool { return true }

このメソッドこそが、最初のコメントで説明されていた「boolFlag interfaceを満たすための特別なメソッド」です。標準のflagパッケージは、フラグの型がIsBoolFlag()というメソッドを持ち、それがtrueを返すかどうかを内部でチェックします。trueだと分かれば、"-v"のように値を書かずに指定しても"-v=true"と同じ意味に解釈してもらえるようになります。

今日覚えて帰ること

Goのinterfaceは「型名の一致」ではなく「必要なメソッド群を持っているか」だけで満たされる。boolValueはBoolFlag interfaceだと一言も書かず、Set/Get/String/IsBoolFlagを実装するだけでflagパッケージに認識される——この暗黙的な仕組みを覚えて帰ろう。
