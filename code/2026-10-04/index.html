OpenCut-app/OpenCut の apps/web/src/hooks/use-mobile.ts を読む

GitHub で実物を見る ↗2026.10.04

OpenCutはブラウザで動く無料・オープンソースの動画編集アプリで、CapCutのようなUIをWebで提供しています。今日選んだのは画面サイズがモバイルかどうかを判定するだけの小さなカスタムフックです。行数は少ないですが、Reactのフックで必ず出てくる「状態管理」「副作用の登録と後始末」「SSR対応」という3つの定番パターンがそのまま詰まっていて、"カスタムフックの書き方"を丸ごと真似できる教材です。

コード

import * as React from "react"

const MOBILE_BREAKPOINT = 768

export function useIsMobile() {
  const [isMobile, setIsMobile] = React.useState<boolean | undefined>(undefined)

  React.useEffect(() => {
    const mql = window.matchMedia(`(max-width: ${MOBILE_BREAKPOINT - 1}px)`)
    const onChange = () => {
      setIsMobile(window.innerWidth < MOBILE_BREAKPOINT)
    }
    mql.addEventListener("change", onChange)
    setIsMobile(window.innerWidth < MOBILE_BREAKPOINT)
    return () => mql.removeEventListener("change", onChange)
  }, [])

  return !!isMobile
}

引用はリポジトリの実物と機械で照合しています。「// …略…」は省略した行です。

上から順に読む

import * as React from "react"

`import * as X from "モジュール名"` は、そのモジュールが持つ全部の機能を `X` という名前の箱にまとめて取り込む書き方です。これ以降、`React.useState` や `React.useEffect` のように `React.` を頭につけて呼び出します。`import { useState } from "react"` のように個別に取り込む書き方もできますが、このファイルは全部 `React.` 経由で統一しています。

const MOBILE_BREAKPOINT = 768

画面幅が何px未満だったら「モバイル」とみなすか、の閾値を定数にしています。768という数字がコードの中に直接埋め込まれる(マジックナンバー)のを避けて、名前付きの定数にすることで、後で読む人にも意味が伝わるようにしています。

export function useIsMobile() {

`export` は、この関数を他のファイルからも `import` して使えるようにする宣言です。関数名が `use` から始まっているのはReactの約束事で、「これはフックです(コンポーネントの中でだけ呼び出せる、状態や副作用を扱う特別な関数です)」という目印になっています。

const [isMobile, setIsMobile] = React.useState<boolean | undefined>(undefined)

`useState(初期値)` は「現在の値」と「その値を更新する関数」の2つをペアで返します。左辺の `const [a, b] = ...` は配列の分割代入で、返ってきた配列の1番目を `isMobile`、2番目を `setIsMobile` という名前で受け取っています。`<boolean | undefined>` は型をコードに明示する書き方(ジェネリクス)で、「isMobileはtrue/falseか、まだ分からない(undefined)状態になり得る」という意味です。初期値をtrue/falseにせず`undefined`にしているのは、このコードがサーバー側で最初に実行される(SSR)ときはブラウザのwindowオブジェクトがまだ無く、画面幅を知る手段がないためです。

React.useEffect(() => {
    // …略…
  }, [])

`useEffect(関数, 依存配列)` は「コンポーネントが画面に表示された後に、何か副作用(DOMを触る、イベントを登録するなど)を実行したい」ときに使います。第2引数の `[]` は空の配列で、「この副作用は依存する値が何も無いので、最初に1回だけ実行してください」という指示です。

const mql = window.matchMedia(`(max-width: ${MOBILE_BREAKPOINT - 1}px)`)

`window.matchMedia(条件)` はブラウザ標準のAPIで、CSSのメディアクエリと同じ書き方の条件(ここでは「画面幅が767px以下か」)を渡すと、その条件が今成立しているか・変化したかを監視できるオブジェクトを返します。バッククォートで囲まれた文字列はテンプレートリテラルで、`${...}` の中にJavaScriptの式(ここでは `MOBILE_BREAKPOINT - 1`)を埋め込めます。

const onChange = () => {
      setIsMobile(window.innerWidth < MOBILE_BREAKPOINT)
    }

useEffectの中で、画面幅が変わったときに呼ばれる関数を定義しています。`window.innerWidth` はブラウザの表示領域の幅(px)で、それが閾値未満かどうかの真偽値を `setIsMobile` に渡して状態を更新しています。この `setIsMobile` を呼ぶと、Reactは `isMobile` の値が変わったことを検知して、このフックを使っているコンポーネントを再描画します。

mql.addEventListener("change", onChange)

先ほどの `mql`(メディアクエリの監視オブジェクト)に対して、「`change` イベント(条件の成立/不成立が切り替わったとき)が起きたら `onChange` を呼んでください」と登録しています。これでユーザーがブラウザの幅を変えるたびに `isMobile` が自動更新されるようになります。

setIsMobile(window.innerWidth < MOBILE_BREAKPOINT)

`addEventListener` は登録した時点ではまだ何も実行されず、次に `change` が起きるまで `onChange` は呼ばれません。そのため、フックが最初に動いた瞬間の「今の画面幅」を使って `isMobile` を一度手動でセットしています。これを忘れると、画面幅が変化するまで `isMobile` が `undefined` のままになってしまいます。

return () => mql.removeEventListener("change", onChange)

`useEffect` に渡した関数が、関数を `return` すると、その返した関数は「クリーンアップ関数」としてReactに扱われます。コンポーネントが画面から消えるときにReactが自動でこの関数を呼び出し、先ほど登録した `change` イベントの監視を解除します。これを書かないと、コンポーネントが消えた後もイベントリスナーが残り続けて、メモリリークの原因になります。

return !!isMobile

`!` は真偽値を反転させる演算子で、`!!x` と2回続けて書くと「xを真偽値に変換する」という意味になります(`!x` で反転し、もう一度 `!` で元の真偽性に戻すことで、型をbooleanに揃えます)。`isMobile` が `undefined` のときは `!!undefined` は `false` になるので、呼び出し側は常に `true`/`false` だけを受け取れて、`undefined` を気にする必要がなくなります。

今日覚えて帰ること

useEffectの中でaddEventListenerのようにイベント登録をしたら、必ず同じ関数の中でreturnする関数を使ってremoveEventListener(後片付け)を書く。登録と解除は常にペアで考える。
