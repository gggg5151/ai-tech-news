yorukot/superfile の src/internal/ui/prompt/tokenize.go を読む

GitHub で実物を見る ↗2026.10.06

superfileはターミナル上で動くファイルマネージャー(TUI)。このファイルがあるpromptパッケージは、ユーザーが入力欄に打ち込んだシェルコマンド文字列（例: echo "hello world" 'a b'）を、実行可能な単語の配列に分割する役割を持っています。今日読むtokenizeWithQuotesは、クォート（" '）とエスケープ（\）を正しく扱いながら1文字ずつ状態を進めていく、短いけれど実務でよく出てくる「状態マシン」パターンの好例です。

コード

// splits command into tokens while respecting quotes and escapes
func tokenizeWithQuotes(command string) ([]string, error) {
	var (
		tokens    []string
		buffer    strings.Builder
		quoteOpen rune // 0:none, '\'' or '"'
		escaped   bool
	)

	// Initialize tokens as empty slice instead of nil
	tokens = []string{}

	// Helper function to flush the current buffer into tokens
	flush := func() {
		tokens = append(tokens, buffer.String())
		buffer.Reset()
	}

	for _, r := range command {
		switch {
		case escaped:
			// Only allow escaping of specific characters that have special meaning
			switch r {
			case '"', '\'', '\\', ' ':
				// These are valid escape sequences
				buffer.WriteRune(r)
			default:
				// Invalid escape sequence - treat backslash as literal
				buffer.WriteRune('\\')
				buffer.WriteRune(r)
			}
			escaped = false
		case r == '\\':
			escaped = true
		case quoteOpen == 0 && (r == '"' || r == '\''):
			quoteOpen = r
		case quoteOpen == r:
			// End of quoted section - always flush (even if empty)
			flush()
			quoteOpen = 0
		case unicode.IsSpace(r) && quoteOpen == 0:
			// Only flush if we have content
			if buffer.Len() > 0 {
				flush()
			}
		default:
			buffer.WriteRune(r)
		}
	}

	if escaped || quoteOpen != 0 {
		return nil, errors.New("unmatched quotes or escape characters in command")
	}

	// Flush any remaining content
	if buffer.Len() > 0 {
		flush()
	}

	return tokens, nil
}

引用はリポジトリの実物と機械で照合しています。「// …略…」は省略した行です。

上から順に読む

func tokenizeWithQuotes(command string) ([]string, error) {

関数定義。引数commandはstring型（コマンド全文の文字列）。戻り値は括弧でくくられた2つ: []string（文字列のスライス＝可変長配列。トークンの一覧）とerror（エラー型。問題なければnilが入る）。Goでは「結果, エラー」という2値返しが標準的な書き方で、呼び出し側は必ずこの両方を受け取って判定します。

var (
		tokens    []string
		buffer    strings.Builder
		quoteOpen rune // 0:none, '\'' or '"'
		escaped   bool
	)

var (...) は複数の変数をまとめて宣言する書き方（1個ずつvar文を書くより読みやすい）。tokensはまだ値を入れていないslice（中身はnil）。strings.Builderは文字列を何度も連結するときに効率よく使える「組み立て用の箱」型です。runeはGoにおける1文字（Unicodeコードポイント）を表す型で、quoteOpenには「今開いているクォート文字」を入れます。初期値は0（コメントの通り何も開いていない状態）。escapedはbool型で、直前の文字が\（バックスラッシュ）だったかどうかを覚えておくフラグです。

// Initialize tokens as empty slice instead of nil
	tokens = []string{}

宣言直後のtokensはnilスライス（要素数0だが型としてはnilとして区別される）です。ここで[]string{}（空のスライスリテラル）を代入し、明示的に「空だけどnilではない」状態にしています。コメントにある通り、これは意図的な設計判断で、後で呼び出し元がtokens == nilで未初期化かどうかを判定したり、JSON化したときにnullではなく[]として出したい場合などに有効な技です。

flush := func() {
		tokens = append(tokens, buffer.String())
		buffer.Reset()
	}

flush := func() {...} は無名関数（名前のない関数）をflushという変数に代入しています。これをクロージャと呼び、関数の中で外側の変数（ここではtokensとbuffer）を直接読み書きできます。中身は、buffer.String()でこれまで溜めた文字列を取り出し、append（スライスに要素を追加する組み込み関数）でtokensの末尾に追加し、buffer.Reset()でbufferを空に戻す、という「今までの単語を確定して次の単語の準備をする」処理です。

for _, r := range command {

for ... range は繰り返し処理の構文。文字列（string）に対してrangeを使うと、バイト単位ではなく1つのUnicode文字（rune）ごとに取り出されます。1つ目の戻り値（インデックス）は_（アンダースコア）で捨てていて使っていません。2つ目のrが今回処理対象の1文字です。

switch {
		case escaped:

switch { case ... } のようにswitchの直後に条件式を書かない形は、Goでは「if-else ifの連鎖」を上から順に評価する書き方として使えます。最初にマッチしたcaseだけが実行されます。ここでは「直前の文字がバックスラッシュだった（escaped==trueだった）」場合を最優先で処理しています。

case '"', '\'', '\\', ' ':
				// These are valid escape sequences
				buffer.WriteRune(r)

escapedだった場合の内側のswitch文です。case '"', '\'', '\\', ' ': はカンマで複数の値を1つのcaseにまとめる書き方（いずれかに一致すればこのブロックを実行）。ダブルクォート・シングルクォート・バックスラッシュ・スペースの4文字だけが「\に続いたときにエスケープが効く」特別な文字と定義されていて、該当すればその文字そのものをbuffer.WriteRune(r)でバッファに書き込みます。該当しない場合はdefaultに落ち、バックスラッシュ自体を無効な指定として文字通り書き戻し（WriteRune('\\')）、続けて元の文字も書き込みます。最後にescaped = falseで「エスケープ待ち」状態を解除します。

case r == '\\':
			escaped = true

外側のswitchに戻ります。今の文字がバックスラッシュそのものだった場合、すぐには書き込まず、escapedをtrueにして「次の1文字は特別扱いする」と予約します。この予約を使うのが1つ上で説明したcase escaped:のブロックです。

case quoteOpen == 0 && (r == '"' || r == '\''):
			quoteOpen = r

&&は論理AND（両方true のときだけ全体がtrue）、||は論理OR（どちらかがtrueなら全体がtrue）です。「今どのクォートも開いていない（quoteOpen == 0）」かつ「今の文字がダブルクォートかシングルクォート」のとき、quoteOpenにその文字を記録して「クォート区間に入った」ことを覚えます。この文字自体はバッファに書き込まれません（クォート記号はトークンの内容には含めない）。

case quoteOpen == r:
			// End of quoted section - always flush (even if empty)
			flush()
			quoteOpen = 0

今開いているクォートと同じ種類の文字が来たら、閉じクォートだと判断します。flush()を呼んで、クォート内に溜めた内容を1トークンとして確定し、quoteOpenを0に戻してクォート区間を終了します。コメントの「even if empty」は、""のように中身が空のクォートでも空文字のトークンとして確定させる、という意図を示しています。

case unicode.IsSpace(r) && quoteOpen == 0:
			// Only flush if we have content
			if buffer.Len() > 0 {
				flush()
			}

unicode.IsSpace(r)は、rが空白文字（スペースやタブなど）かどうかを判定する標準ライブラリの関数です。クォートの外にいるときに空白が来たら単語の区切りとみなしますが、buffer.Len() > 0（バッファに何か文字が溜まっている）場合だけflush()します。これにより "a b" のように空白が連続しても空のトークンが量産されないようになっています。

default:
			buffer.WriteRune(r)
		}

上のどのcaseにも当てはまらない、ごく普通の文字（クォート記号でもバックスラッシュでも空白でもない文字）はここに来て、そのままbufferに書き込まれます。switch全体はここで閉じられます。

if escaped || quoteOpen != 0 {
		return nil, errors.New("unmatched quotes or escape characters in command")
	}

forループを抜けた後の検証です。コマンド文字列の最後までescapedがtrueのまま（末尾が\で終わっている）、またはquoteOpenが0以外のまま（クォートが閉じられていない）だった場合は、入力が不完全だったと判断し、errors.New(...)でエラーメッセージを作って返します。1つ目の戻り値をnilにしているのは、エラーがある場合はトークン結果を使わない、というGoの作法です。

if buffer.Len() > 0 {
		flush()
	}

	return tokens, nil

最後に、バッファにまだ書き込み済みの文字が残っていれば（コマンドが空白以外の文字で終わっていた場合）、最後のflush()で1つのトークンとして確定させます。そして完成したtokensスライスと、エラーなしを示すnilを返して関数が終わります。

今日覚えて帰ること

1文字ずつ読みながら「今どういう状態か（クォート中か、エスケープ待ちか）」をruneやboolの変数で持ち、switch{case ...}で分岐するのは、パーサーやトークナイザーを書くときの基本パターン。条件式なしのswitchはif-else連鎖の読みやすい代替になることを覚えておくと役立つ。
