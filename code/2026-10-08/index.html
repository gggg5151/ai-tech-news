aquasecurity/trivy の pkg/dependency/parser/golang/sum/parse.go を読む

GitHub で実物を見る ↗2026.10.08

Trivyはコンテナイメージやコードリポジトリの脆弱性・設定ミスを検出するスキャナーです。依存関係を正しく把握するために、様々な言語のロックファイルを解析するパーサーを言語ごとに持っています。今回読むのはGoの`go.sum`ファイル(依存パッケージのハッシュ値一覧)を解析する部分です。ファイルをテキストとして読み、必要な情報だけ抜き出して構造体のスライスに変換する、実務でよくある「パーサーを書く」パターンがコンパクトに詰まっています。

コード

// Parse parses a go.sum file
func (p *Parser) Parse(_ context.Context, r xio.ReadSeekerAt) ([]ftypes.Package, []ftypes.Dependency, error) {
	var pkgs []ftypes.Package
	uniquePkgs := make(map[string]string)

	scanner := bufio.NewScanner(r)
	for scanner.Scan() {
		line := strings.TrimSpace(scanner.Text())
		s := strings.Fields(line)
		if len(s) < 2 {
			continue
		}

		// go.sum records and sorts all non-major versions
		// with the latest version as last entry
		uniquePkgs[s[0]] = strings.TrimSuffix(s[1], "/go.mod")
	}
	if err := scanner.Err(); err != nil {
		return nil, nil, xerrors.Errorf("scan error: %w", err)
	}

	for k, v := range uniquePkgs {
		pkgs = append(pkgs, ftypes.Package{
			ID:      dependency.ID(ftypes.GoModule, k, v),
			Name:    k,
			Version: v,
		})
	}

	return pkgs, nil, nil
}

引用はリポジトリの実物と機械で照合しています。「// …略…」は省略した行です。

上から順に読む

func (p *Parser) Parse(_ context.Context, r xio.ReadSeekerAt) ([]ftypes.Package, []ftypes.Dependency, error) {

`(p *Parser)`はメソッドのレシーバです。`Parser`という構造体に`Parse`というメソッドを紐付けています。`*Parser`の`*`は「ポインタ型」を意味し、構造体のコピーではなく元のデータへの参照を受け取ります。引数`_ context.Context`の`_`はGoのブランク識別子で、「この引数は受け取るが使わない」ことを明示する書き方です(キャンセル処理など他の実装では使うため型だけ揃えている)。戻り値は`()`で囲んで3つ並べており、Goの関数は複数の値を同時に返せます。ここでは「パッケージ一覧」「依存関係一覧」「エラー」の3つです。

var pkgs []ftypes.Package

`var 変数名 型`という宣言文です。`[]ftypes.Package`は`ftypes.Package`型の要素を持つスライス(可変長配列)を表します。初期値を書いていないので`pkgs`はまだ要素のない`nil`スライスとして始まります。Goでは`nil`スライスに対して後述の`append`を呼んでも安全に動きます。

uniquePkgs := make(map[string]string)

`:=`は「型を明示せず、右辺の値から型を推論して新しい変数を作る」代入です。`make(map[string]string)`は空のmap(辞書)を作る組み込み関数で、キーと値がどちらも`string`型のmapを生成します。この後、パッケージ名をキー、バージョンを値として使い、同じパッケージ名の重複を自然に防ぐための入れ物として使われます。

scanner := bufio.NewScanner(r)
	for scanner.Scan() {

`bufio.NewScanner(r)`は、ファイルの中身を1行ずつ読み進めるための`Scanner`を作ります。`r`は関数の引数で受け取ったファイルのようなもの(読み取り可能なデータ源)です。`for scanner.Scan() { ... }`は「次の行があるかぎり繰り返す」ループです。`Scan()`は次の行を読み込めたら`true`、ファイルの終わりに達したら`false`を返すので、これがそのままループの継続条件になっています。

line := strings.TrimSpace(scanner.Text())

`scanner.Text()`は直前に`Scan()`で読み込んだ1行分の文字列を返します。`strings.TrimSpace(...)`はその文字列の先頭と末尾にある空白文字(スペースや改行など)を取り除きます。go.sumのファイルは行末に余分な空白が入ることがあるため、このひと手間で以降の処理を安定させています。

s := strings.Fields(line)

`strings.Fields(line)`は、文字列を空白(スペースやタブ)で区切って単語ごとの`[]string`(文字列のスライス)に分割します。go.sumの1行は`モジュール名 バージョン ハッシュ値`のようにスペース区切りになっているので、これで`s[0]`がモジュール名、`s[1]`がバージョン情報として取り出せるようになります。

if len(s) < 2 {
			continue
		}

`len(s)`はスライス`s`の要素数を返します。分割した結果が2つ未満(つまりモジュール名とバージョンの両方が揃っていない)なら、その行は想定外のフォーマットとして無視します。`continue`はループの残りの処理をスキップして次の繰り返しに進む文です。こうした「異常値はスキップして先に進む」防御的な書き方は、外部ファイルを読むパーサーでは定番です。

// go.sum records and sorts all non-major versions
		// with the latest version as last entry
		uniquePkgs[s[0]] = strings.TrimSuffix(s[1], "/go.mod")

コメントは「go.sumは同じモジュールの複数バージョンを記録し、最新バージョンを最後に並べている」という事実を説明しています。`strings.TrimSuffix(s[1], "/go.mod")`はバージョン文字列の末尾に`/go.mod`が付いていれば取り除く処理です(go.sumにはバージョンそのものと、そのgo.modファイルのハッシュの2種類の行があるため)。`uniquePkgs[s[0]] = ...`はmapへの書き込みで、同じキー(モジュール名)に対して複数回書き込むと後の値で上書きされます。go.sumが古いバージョンから新しいバージョンの順に並んでいることを利用し、ループを最後まで回すと自然に「各モジュールの最新バージョンだけが残る」仕組みになっています。

if err := scanner.Err(); err != nil {
		return nil, nil, xerrors.Errorf("scan error: %w", err)
	}

`if err := scanner.Err(); err != nil { ... }`は、Goで非常によく使われる書き方です。`if`文の中で`:=`を使って変数`err`を宣言しつつ、その直後にセミコロンで区切って条件式`err != nil`を書いています。`scanner.Err()`はループ中に読み込みエラーが起きていたかを確認するメソッドで、ループを抜けた後に呼ぶのが定石です。エラーがあれば`xerrors.Errorf("scan error: %w", err)`で元のエラーを`%w`でラップ(包んで)し、「どこでどんなエラーが起きたか」の情報を保ったまま呼び出し元に返します。3つの戻り値のうち使わない`pkgs`と`dependencies`には`nil`を入れています。

for k, v := range uniquePkgs {

`range`はスライスやmapなどの「コレクション」を順番に取り出すための構文です。mapに対して使うと、1回のループで「キー」と「値」の2つを同時に受け取れます。ここでは`k`にモジュール名、`v`にバージョンが入ります。mapの反復順序はGoの仕様上保証されていない(実行するたびに順番が変わりうる)ため、ここでの順序は結果に影響しません。

pkgs = append(pkgs, ftypes.Package{
			ID:      dependency.ID(ftypes.GoModule, k, v),
			Name:    k,
			Version: v,
		})

`ftypes.Package{ ID: ..., Name: ..., Version: ... }`は構造体リテラルで、フィールド名を指定しながらその場で値を詰めた構造体を作る書き方です。`append(pkgs, ...)`はスライス`pkgs`の末尾に新しい要素を追加した「新しいスライス」を返す組み込み関数で、`pkgs = append(...)`のように元の変数に再代入するのが決まった使い方です。これをmapの全要素についてループで繰り返すことで、mapの中身を最終的なスライス形式に変換しています。

dependency.ID(ftypes.GoModule, k, v)

`dependency.ID`は別パッケージ(`dependency`)にある関数の呼び出しです。パッケージ種別(`ftypes.GoModule`)、モジュール名`k`、バージョン`v`の3つから、Trivy内部で一意に識別するためのID文字列を組み立てています。パーサー自身はID生成ロジックの詳細を知らなくても、専用の関数に委譲することで責務を分離している例です。

return pkgs, nil, nil

関数の最後で3つの戻り値をまとめて返しています。1つ目は組み立てた`pkgs`、2つ目の依存関係リストはgo.sumからは「どのパッケージが何に依存しているか」という親子関係までは分からないため`nil`(空)、3つ目のエラーも正常終了なので`nil`です。呼び出し元はこの3つを順番に受け取って処理を続けます。

今日覚えて帰ること

Goでは「mapに書き込んで重複を自然に消し、range+appendでスライスに変換する」という組み合わせが、ユニークな集合を作る定番パターンです。
