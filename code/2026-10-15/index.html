gtsteffaniak/filebrowser の backend/internal/utils/crypto.go を読む

GitHub で実物を見る ↗2026.10.15

filebrowserはGoで書かれたWeb版ファイラーで、スター8,700超の実運用プロダクトです。backend/internal/utils/crypto.goにはパスワードハッシュやトークン署名などの暗号系ユーティリティが集まっています。その中からHMACで「改ざんされていないか検証できる文字列トークン」を作る2つの関数を選びました。Cookieやメール内の確認リンクなどで、サーバーが発行した値を後から検証したい場面でよく使われるパターンで、1年目でもすぐ応用できる実務的なコードです。

コード

func HashSHA256(data string) string {
	bytes := sha256.Sum256([]byte(data))
	return hex.EncodeToString(bytes[:])
}

// SignHMACSHA256Base64URL returns base64url(payload).base64url(hmac-sha256 signature).
func SignHMACSHA256Base64URL(key, payload []byte) string {
	payloadB64 := base64.RawURLEncoding.EncodeToString(payload)
	mac := hmac.New(sha256.New, key)
	mac.Write([]byte(payloadB64))
	signature := base64.RawURLEncoding.EncodeToString(mac.Sum(nil))
	return payloadB64 + "." + signature
}

// VerifyHMACSHA256Base64URL validates token form and returns the decoded payload.
func VerifyHMACSHA256Base64URL(key []byte, token string) ([]byte, bool) {
	parts := strings.Split(token, ".")
	if len(parts) != 2 {
		return nil, false
	}
	payloadB64, signature := parts[0], parts[1]

	mac := hmac.New(sha256.New, key)
	mac.Write([]byte(payloadB64))
	expectedSignature := base64.RawURLEncoding.EncodeToString(mac.Sum(nil))
	if !hmac.Equal([]byte(signature), []byte(expectedSignature)) {
		return nil, false
	}

	payload, err := base64.RawURLEncoding.DecodeString(payloadB64)
	if err != nil {
		return nil, false
	}
	return payload, true
}

引用はリポジトリの実物と機械で照合しています。「// …略…」は省略した行です。

上から順に読む

func HashSHA256(data string) string {

関数定義です。func の後に関数名HashSHA256、カッコの中に引数（data string、つまりstring型の変数data）、その後ろの戻り値の型（string）が続きます。Goでは「引数の型は変数名の後」という順序で書くのが特徴です。

bytes := sha256.Sum256([]byte(data))

`:=`は「新しい変数を宣言しつつ代入する」演算子です。`[]byte(data)`はstring型のdataをbyteのスライス（可変長配列のようなもの）に変換しています。暗号処理の関数はほとんどbyte列を要求するので、文字列→byte列の変換はGoの暗号コードで非常によく出てくる定型句です。sha256.Sum256はSHA-256ハッシュ値を計算し、32バイト固定長の配列（[32]byte）を返します。

return hex.EncodeToString(bytes[:])

`bytes[:]`は配列をスライスに変換する書き方です（先頭から末尾までを指定しないスライス式）。hex.EncodeToStringはbyte列を16進数文字列（0-9, a-f）に変換します。つまりこの関数は「文字列を受け取り、そのSHA-256ハッシュを16進数文字列として返す」処理をしています。

func SignHMACSHA256Base64URL(key, payload []byte) string {

引数が2つ(key, payload)とも同じ型[]byteの場合、Goでは型名を最後にまとめて1回だけ書けます。これは「key []byte, payload []byte」と書くのと全く同じ意味です。「鍵（key）とデータ（payload）を受け取り、署名付きトークン文字列を返す」関数です。

payloadB64 := base64.RawURLEncoding.EncodeToString(payload)

RawURLEncodingは、URLやファイル名に安全に使える文字（+や/の代わりに-や_を使う）でBase64エンコードし、さらに末尾の `=` パディングを付けないエンコード方式です。CookieやURLクエリに値を埋め込むときにこの方式が好まれます。

mac := hmac.New(sha256.New, key)

HMACとは「秘密鍵を使ってハッシュ値を計算する」改ざん検知の仕組みです。hmac.Newはハッシュ計算オブジェクト（Go用語でhash.Hashというインターフェース）を作るための関数で、第一引数には「どのハッシュ関数を使うか」を渡します。sha256.New自体は関数ですが、ここでは呼び出さずに関数そのもの（関数値）として渡している点に注目してください。

mac.Write([]byte(payloadB64))

Writeメソッドは、macの内部状態にbyte列を取り込みます。戻り値を使っていないので無視していますが、実際は書き込んだバイト数とエラーを返せる設計です（ここでは常に成功するため無視しても問題ありません）。この行の後、macの中には「key + payloadB64」から計算中のハッシュ状態が保持されています。

signature := base64.RawURLEncoding.EncodeToString(mac.Sum(nil))

mac.Sum(nil)は、これまで書き込んだデータに対する最終的なHMAC値（byte列）を計算して返します。引数にnilを渡すと「新しいスライスを作ってそこに結果を入れて返す」という意味になります（既存のスライスの末尾に追記したい場合はnil以外を渡せます）。その結果をまたURL安全なBase64文字列に変換しています。

return payloadB64 + "." + signature

Goの文字列は `+` でそのまま連結できます。ここでは「データ部分」と「署名部分」をピリオドで区切った1本の文字列（例: `abc123.xyz789`）を作って返しています。この形式がトークン全体になります。

func VerifyHMACSHA256Base64URL(key []byte, token string) ([]byte, bool) {

Goの関数は複数の値を同時に返せます。ここでは「復号したpayload（[]byte）」と「検証が成功したか（bool）」の2つをカッコで囲んで返り値リストとして宣言しています。呼び出し側は `payload, ok := VerifyHMACSHA256Base64URL(...)` のように2つ同時に受け取ります。

parts := strings.Split(token, ".")
	if len(parts) != 2 {
		return nil, false
	}

strings.Splitは文字列をピリオドで分割し、文字列のスライスを返します。「ピリオドで区切った2つの部分があるはずだ」という前提をlen(parts) != 2でチェックし、形式が壊れていたら即座に失敗（nilとfalse）を返しています。Goでは早期リターンで異常系を先に処理するのが一般的な書き方です。

payloadB64, signature := parts[0], parts[1]

1行で2つの変数に同時に値を代入しています。右辺もカンマで区切って複数の値を並べれば、左辺の変数にそれぞれ順番に対応づけられます。

if !hmac.Equal([]byte(signature), []byte(expectedSignature)) {
		return nil, false
	}

受け取った署名(signature)と、自分で鍵を使って再計算した署名(expectedSignature)を比較しています。ここで単純な `==` ではなくhmac.Equalを使うのが重要なポイントです。`==` だと文字が一致しない箇所で比較が早く終わるため、攻撃者が応答速度の差から正しい署名を推測できてしまう可能性があります（タイミング攻撃）。hmac.Equalは常に同じ時間がかかる「定数時間比較」で、これを防ぎます。

今日覚えて帰ること

署名付きトークンを検証するときは文字列の `==` ではなく、常に `hmac.Equal`（定数時間比較）を使うこと。比較にかかる時間の差から答えを推測される「タイミング攻撃」を防ぐためです。
