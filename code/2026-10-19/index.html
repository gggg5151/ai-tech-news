github/github-mcp-server の internal/requeststate/sealer.go を読む

GitHub で実物を見る ↗2026.10.19

github-mcp-serverはGitHub公式のMCP(Model Context Protocol)サーバー実装です。AIエージェントがGitHubのIssueやPRを操作するためのツール群を提供しています。このファイルは、MCPサーバーがリクエストの状態（例えばページネーションの続き情報など）をクライアントに渡すとき、中身を暗号化してURLセーフな文字列にする「Sealer」という仕組みです。標準ライブラリの`crypto`パッケージだけで暗号化・復号を実装している、Goらしいコンパクトなコードなので教材に選びました。

コード

// Seal encrypts and authenticates plaintext into a URL-safe opaque token.
func (s *Sealer) Seal(_ context.Context, plaintext []byte) (string, error) {
	nonce := make([]byte, s.aead.NonceSize())
	if _, err := rand.Read(nonce); err != nil {
		return "", fmt.Errorf("generating nonce: %w", err)
	}
	sealed := s.aead.Seal(nonce, nonce, plaintext, nil)
	return base64.RawURLEncoding.EncodeToString(sealed), nil
}

// Open verifies and decrypts a token produced by Seal.
func (s *Sealer) Open(token string) ([]byte, error) {
	if token == "" {
		return nil, errors.New("empty token")
	}
	sealed, err := base64.RawURLEncoding.DecodeString(token)
	if err != nil {
		return nil, fmt.Errorf("decoding token: %w", err)
	}
	nonceSize := s.aead.NonceSize()
	if len(sealed) < nonceSize {
		return nil, errors.New("token is too short")
	}
	plaintext, err := s.aead.Open(nil, sealed[:nonceSize], sealed[nonceSize:], nil)
	if err != nil {
		return nil, fmt.Errorf("opening token: %w", err)
	}
	return plaintext, nil
}

引用はリポジトリの実物と機械で照合しています。「// …略…」は省略した行です。

上から順に読む

func (s *Sealer) Seal(_ context.Context, plaintext []byte) (string, error) {

`func (s *Sealer) Seal(...)` は「メソッド」の定義です。`(s *Sealer)` の部分は「レシーバ」と呼ばれ、`Sealer`型の値に対してこのメソッドを呼べるようにしています。`*Sealer`の`*`は「ポインタ」を意味し、`s`はSealer構造体のコピーではなく元の実体そのものを指します（構造体の中身を書き換えたいとき・コピーのコストを避けたいときにポインタレシーバを使います）。引数の`_ context.Context`は、型は`context.Context`だが変数名を`_`にすることで「この引数は受け取るが中では使わない」と明示しています。戻り値は`(string, error)`の2つで、Goでは関数が複数の値を返せます。1つ目が本来の結果、2つ目がエラー（なければ`nil`）という組み合わせはGoの定番パターンです。

nonce := make([]byte, s.aead.NonceSize())

`make([]byte, N)` は、長さNの`[]byte`（バイトのスライス、つまり可変長配列のようなもの）を生成し、全要素を0で初期化します。`s.aead.NonceSize()`は、暗号方式が要求する「ノンス（nonce: 一度しか使わない値）」の長さをバイト数で返すメソッド呼び出しです。ここではまだ空のバイト列を用意しただけです。

if _, err := rand.Read(nonce); err != nil {
		return "", fmt.Errorf("generating nonce: %w", err)
	}

`rand.Read(nonce)`は暗号的に安全な乱数で`nonce`のスライスを埋め、埋めたバイト数とエラーの2つを返します。`_, err :=`は1つ目の戻り値（バイト数）を使わない宣言で、`:=`は新しい変数`err`を宣言しつつ代入する記法です。`if ...; err != nil {`は「ifの条件の前に一度だけ実行する文を書く」Go特有の書き方で、ここでは関数呼び出しと同時にエラーチェックしています。エラーがあれば`fmt.Errorf("...: %w", err)`で元のエラーを文脈とともにラップして返します。`%w`は元のエラーを後で`errors.Is`や`errors.As`で検査できる形で包み込む書式指定子です。戻り値の1つ目が`""`（空文字列）になっているのは、Goでは`error`以外の戻り値も必ず何かを返す必要があるためで、エラー時は「ゼロ値」を返すのが慣習です。

sealed := s.aead.Seal(nonce, nonce, plaintext, nil)

`s.aead`は`cipher.AEAD`という暗号化・認証を同時に行うインターフェース型の値です。`Seal(dst, nonce, plaintext, additionalData)`というメソッドで、第1引数`dst`に渡したスライスの末尾に暗号文を追記して返す仕組みになっています。ここでは`dst`としても`nonce`自身を渡しているので、結果の`sealed`は「nonce本体＋暗号化された本文」が1本のバイト列として連結されたものになります。あとで復号するときにnonceが必要なので、先頭に埋め込んでおくのは暗号処理でよく使われる工夫です。

return base64.RawURLEncoding.EncodeToString(sealed), nil

`sealed`は生のバイト列なので、そのままではURLやJSONの文字列として扱いにくい文字（改行や`+`、`/`など）を含む可能性があります。`base64.RawURLEncoding.EncodeToString(...)`はバイト列を、URLに安全に載せられる文字だけで構成されたBase64文字列に変換します。「Raw」は末尾のパディング文字`=`を付けないことを意味し、「URL」は`+`や`/`の代わりにURLで問題を起こさない文字を使うことを意味します。これが正常時の最終的な戻り値（文字列）で、2つ目の`nil`はエラーが無いことを表します。

func (s *Sealer) Open(token string) ([]byte, error) {
	if token == "" {
		return nil, errors.New("empty token")
	}

`Open`はSealで作ったトークンを元に戻す（復号する）メソッドです。最初に`token == ""`で空文字列かどうかを素朴にチェックし、空であれば`errors.New("empty token")`で新しいエラー値を作って即座に返します。`errors.New`は固定の文字列からエラーを作る最もシンプルな方法で、文脈を埋め込みたい`fmt.Errorf`とは使い分けます。

sealed, err := base64.RawURLEncoding.DecodeString(token)
	if err != nil {
		return nil, fmt.Errorf("decoding token: %w", err)
	}

Sealでエンコードした文字列を、`DecodeString`で元のバイト列に戻します。ここでも「関数を呼んで結果とエラーを受け取り、すぐエラーをチェックする」というGoの定型パターンが繰り返されています。デコードに失敗する（不正な文字列が渡された）場合は、やはり`%w`でラップしたエラーを返します。

nonceSize := s.aead.NonceSize()
	if len(sealed) < nonceSize {
		return nil, errors.New("token is too short")
	}

復号したバイト列の先頭`nonceSize`バイトがnonceであるはずなので、まずその長さを取得します。`len(sealed)`はスライスの長さ（要素数）を返す組み込み関数です。もしデコードされたバイト列がnonceの長さより短ければ、改ざんされたトークンか不正な入力なので、ここで早期にエラーを返して以降の処理に進まないようにしています。こうした「想定より短い・おかしい入力を早めに弾く」チェックは、バッファの範囲外アクセスを防ぐための基本的な防御的プログラミングです。

plaintext, err := s.aead.Open(nil, sealed[:nonceSize], sealed[nonceSize:], nil)

`sealed[:nonceSize]`は「先頭からnonceSize個まで」を切り出すスライス式で、これが元のnonceです。`sealed[nonceSize:]`は「nonceSizeから末尾まで」で、これが本来の暗号文部分です。`s.aead.Open(dst, nonce, ciphertext, additionalData)`は、Sealと対になる復号・検証メソッドで、nonceと暗号文が正しく対応し、かつ改ざんされていないことを確認したうえで平文を返します。第1引数の`nil`は「結果を追記する先のバッファは特に用意しない」という意味です。

if err != nil {
		return nil, fmt.Errorf("opening token: %w", err)
	}
	return plaintext, nil

復号・検証に失敗した場合（改ざんされていた、鍵が違う、などの理由であり得ます）は、エラーをラップして返します。成功した場合は、復号できた平文のバイト列`plaintext`とエラーなし（`nil`）を返して処理を終えます。SealとOpenが対になっていて、Sealで組み立てた順序（nonce→暗号文）をOpenで同じ順序で分解している点が、このコード全体の設計の要です。

今日覚えて帰ること

暗号化トークンを作るときは「ノンス（nonce）を暗号文の先頭に結合してbase64エンコードする」のが定番パターン。復号側は同じ順序でスライスを切り分ければ対になる処理が書ける。
