gogs/gogs の internal/sync/exclusive_pool.go を読む

GitHub で実物を見る ↗2026.10.20

gogsはGoで書かれた自己ホスト型のGitサーバーです。本体のWebルーティングやDB層は量が多いので、今日は内部ユーティリティの`internal/sync`パッケージから、ファイルシステム上の同じリソース（例: 同じリポジトリ）を複数のgoroutine（Goの軽量スレッド）が同時に触らないようにする「名前付きロック」の実装を選びました。ファイル全体が66行で完結しており、Goの並行処理の基本イディオム（mutex、map、ポインタ、defer）が一度に学べます。

コード

package sync

import (
	"sync"
)

// ExclusivePool is a pool of non-identical instances
// that only one instance with same identity is in the pool at a time.
// In other words, only instances with different identities can be in
// the pool the same time. If another instance with same identity tries
// to get into the pool, it hangs until previous instance left the pool.
//
// This pool is particularly useful for performing tasks on same resource
// on the file system in different goroutines.
type ExclusivePool struct {
	lock sync.Mutex

	// pool maintains locks for each instance in the pool.
	pool map[string]*sync.Mutex

	// count maintains the number of times an instance with same identity checks in
	// to the pool, and should be reduced to 0 (removed from map) by checking out
	// with same number of times.
	// The purpose of count is to delete lock when count down to 0 and recycle memory
	// from map object.
	count map[string]int
}

// NewExclusivePool initializes and returns a new ExclusivePool object.
func NewExclusivePool() *ExclusivePool {
	return &ExclusivePool{
		pool:  make(map[string]*sync.Mutex),
		count: make(map[string]int),
	}
}

// CheckIn checks in an instance to the pool and hangs while instance
// with same identity is using the lock.
func (p *ExclusivePool) CheckIn(identity string) {
	p.lock.Lock()

	lock, has := p.pool[identity]
	if !has {
		lock = &sync.Mutex{}
		p.pool[identity] = lock
	}
	p.count[identity]++

	p.lock.Unlock()
	lock.Lock()
}

// CheckOut checks out an instance from the pool and releases the lock
// to let other instances with same identity to grab the lock.
func (p *ExclusivePool) CheckOut(identity string) {
	p.lock.Lock()
	defer p.lock.Unlock()

	p.pool[identity].Unlock()
	if p.count[identity] == 1 {
		delete(p.pool, identity)
		delete(p.count, identity)
	} else {
		p.count[identity]--
	}
}

引用はリポジトリの実物と機械で照合しています。「// …略…」は省略した行です。

上から順に読む

package sync

import (
	"sync"
)

1行目の`package sync`はこのファイルが属するパッケージ名の宣言です（gogs独自の`internal/sync`パッケージで、1行目は単にそのパッケージ名が`sync`だと言っているだけ）。続く`import ("sync")`は標準ライブラリの`sync`パッケージを読み込んでいます。名前が同じでも、自分のパッケージ名と標準ライブラリのパッケージ名は別物として扱われ、コード中では`sync.Mutex`のように書くことで「標準ライブラリのsync」だと明示できます。

type ExclusivePool struct {
	lock sync.Mutex

	pool map[string]*sync.Mutex

	count map[string]int
}

`type 名前 struct { ... }`は複数のフィールド（データ）をまとめた新しい型を定義する構文です。`sync.Mutex`は標準ライブラリが提供する「排他ロック」で、`Lock()`を呼ぶと誰かが使用中なら待たされ、`Unlock()`で解放します。`map[string]*sync.Mutex`は「キーが`string`、値が`*sync.Mutex`（Mutexへのポインタ）」の辞書（map）です。値がポインタなのは、Mutexを値コピーしてしまうと別々の実体になって排他の意味が壊れるため、必ず同じアドレスを指す形で共有する必要があるからです。`map[string]int`は識別子ごとの利用回数を数えるための辞書です。

func NewExclusivePool() *ExclusivePool {
	return &ExclusivePool{
		pool:  make(map[string]*sync.Mutex),
		count: make(map[string]int),
	}
}

Goにはクラスのコンストラクタがないので、`New型名`という名前の関数を用意するのが慣習です。`&ExclusivePool{...}`は構造体リテラル（フィールドに値を入れて構造体を作る書き方）の前に`&`を付けて、その構造体の「アドレス（ポインタ）」を作っています。戻り値の型`*ExclusivePool`の`*`はポインタ型であることを示します。mapはGoでは使う前に`make`で初期化しないと書き込めない（nilマップへの書き込みはパニックする）ため、`make(map[string]*sync.Mutex)`のように明示的に生成しています。

func (p *ExclusivePool) CheckIn(identity string) {

関数名の前にある`(p *ExclusivePool)`は「メソッドのレシーバ」です。これにより`CheckIn`は`ExclusivePool`型に紐づくメソッドになり、呼び出し側は`pool.CheckIn("foo")`のように書けます。レシーバがポインタ（`*ExclusivePool`）なので、メソッド内で`p`のフィールドを書き換えると呼び出し元の実体にも反映されます（値レシーバだとコピーに対する変更になり反映されません）。

p.lock.Lock()

	lock, has := p.pool[identity]
	if !has {
		lock = &sync.Mutex{}
		p.pool[identity] = lock
	}
	p.count[identity]++

	p.lock.Unlock()
	lock.Lock()

まず構造体全体を守る`p.lock`をロックし、mapを安全に読み書きできる状態にします。`lock, has := p.pool[identity]`はGoのmapアクセスの定番イディオムで、2つ目の戻り値`has`（真偽値）はそのキーが存在したかどうかを表します。存在しなければ`&sync.Mutex{}`で新しいMutexを作り（ゼロ値のMutexはそのまま使える初期状態なので初期化不要）、mapに登録します。`p.count[identity]++`は、そのidentityを使っている人数（回数）をカウントアップします。mapの値が整数で、まだキーが存在しない場合は自動的にゼロ値`0`として扱われるため、初回は`0++`で`1`になります。その後`p.lock.Unlock()`で構造体全体のロックを先に解放し（他のidentityを待つgoroutineをブロックしないため）、最後に`lock.Lock()`でこのidentity専用のロックを取りに行きます。ここでブロックされるのは、同じidentityを使う別のgoroutineがまだ`CheckOut`していない場合だけです。

func (p *ExclusivePool) CheckOut(identity string) {
	p.lock.Lock()
	defer p.lock.Unlock()

`defer p.lock.Unlock()`の`defer`は「この関数がどこで終わっても、関数を抜ける直前に必ず実行する」という予約です。`Lock()`した直後に`defer Unlock()`と書くのはGoでロックを使うときの定番パターンで、途中にreturnや予期しないエラーがあってもUnlock漏れを防げます。

p.pool[identity].Unlock()
	if p.count[identity] == 1 {
		delete(p.pool, identity)
		delete(p.count, identity)
	} else {
		p.count[identity]--
	}

まず`p.pool[identity].Unlock()`でこのidentity専用のロックを解放し、同じidentityを待っている次のgoroutineに権利を渡します。続いて利用者数をチェックし、残り利用者が自分だけ（カウントが1）なら`delete(map, key)`で`pool`と`count`両方からそのidentityのエントリを削除します。これをしないと、一度使われたidentityのMutexがいつまでもmapに残り続けてメモリを食い続けてしまうため、使い終わったら掃除するという設計です。利用者がまだ他にもいる（カウントが2以上）場合は削除せず、カウントを1減らすだけにします。

今日覚えて帰ること

複数のgoroutineから「同じキーだけ」を排他制御したいときは、グローバルな1つのMutexで全部をロックするのではなく、map[string]*sync.Mutexで識別子ごとに別のロックを持たせると、無関係なキー同士は並行して動ける。ただしmapにロックを増やし続けるとメモリが漏れるので、利用回数をカウントして0になったらdeleteで掃除する、という後始末まで含めて覚えておくと実務で使えるパターンになる。
