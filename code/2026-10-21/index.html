gitleaks/gitleaks の config/allowlist.go を読む

GitHub で実物を見る ↗2026.10.21

gitleaksはGitリポジトリから漏洩したAPIキーなどを検出するCLIツールで、Goらしいシンプルな構造とプロダクション品質のエラーハンドリングが学びやすいリポジトリです。config/allowlist.goは「誤検知として無視してよい条件（特定のコミット・パス・正規表現・ストップワード）」を表すAllowlist構造体を定義しています。今回取り上げるValidate()メソッドは、ユーザー設定を安全な内部表現に変換する前処理で、mapを使った重複排除、外部ライブラリのメソッドチェーン、一度きりの初期化フラグなど、1年目が実務で頻繁に出会うGoのイディオムが凝縮されています。

func (a *Allowlist) Validate() error {
	if a.validated {
		return nil
	}

	// Disallow empty allowlists.
	if len(a.Commits) == 0 &&
		len(a.Paths) == 0 &&
		len(a.Regexes) == 0 &&
		len(a.StopWords) == 0 {
		return errors.New("must contain at least one check for: commits, paths, regexes, or stopwords")
	}

	// Deduplicate commits and stopwords.
	if len(a.Commits) > 0 {
		uniqueCommits := make(map[string]struct{})
		for _, commit := range a.Commits {
			// Commits are case-insensitive.
			uniqueCommits[strings.TrimSpace(strings.ToLower(commit))] = struct{}{}
		}
		a.Commits = maps.Keys(uniqueCommits)
		a.commitMap = uniqueCommits
	}
	if len(a.StopWords) > 0 {
		uniqueStopwords := make(map[string]struct{})
		for _, stopWord := range a.StopWords {
			uniqueStopwords[strings.ToLower(stopWord)] = struct{}{}
		}

		values := maps.Keys(uniqueStopwords)
		a.StopWords = values
		a.stopwordTrie = ahocorasick.NewTrieBuilder().AddStrings(values).Build()
	}

	// Combine patterns into a single expression.
	if len(a.Paths) > 0 {
		a.pathPat = joinRegexOr(a.Paths)
	}
	if len(a.Regexes) > 0 {
		a.regexPat = joinRegexOr(a.Regexes)
	}

	a.validated = true
	return nil
}

引用はリポジトリの実物と機械で照合しています。「// …略…」は省略した行です。

上から順に読む

func (a *Allowlist) Validate() error {

Goではメソッドを関数と区別するために「レシーバ」を書きます。`(a *Allowlist)` がレシーバで、「この関数はAllowlist型の値にくっつくメソッドですよ」という宣言です。`*Allowlist` の `*` はポインタ型を表し、「Allowlist構造体そのものではなく、それが置かれているメモリ上の場所への参照」を意味します。ポインタレシーバにする理由は、このメソッドの中で `a.commitMap` や `a.validated` といったフィールドを書き換えたいからです。値レシーバ（`*`なし）だとコピーに対して書き込むだけで元のデータは変わりません。戻り値の `error` はGoで「失敗するかもしれない処理」の定番の型で、呼び出し側は `if err := x.Validate(); err != nil { ... }` のようにチェックします。

if a.validated {
		return nil
	}

`a.validated` はAllowlist構造体に定義されている bool 型のフィールドで、「このメソッドをもう実行済みか」を覚えておくためのフラグです。もしすでに検証・変換済みなら、重い処理（後述のmap作成やトライ木構築）をもう一度やらずに `nil`（エラーなし）を返して即終了します。Goにはコンストラクタがないので、こうした「初回だけ初期化する」パターンは構造体のメソッドの先頭でフラグを見る、という書き方でよく実現されます。

if len(a.Commits) == 0 &&
		len(a.Paths) == 0 &&
		len(a.Regexes) == 0 &&
		len(a.StopWords) == 0 {
		return errors.New("must contain at least one check for: commits, paths, regexes, or stopwords")
	}

`len()` はスライス（可変長配列）やmapの要素数を返す組み込み関数です。ここでは4つのスライスフィールドが全部空かどうかを `&&`（論理AND）でつないで判定しています。Goは1つの条件式を複数行に分けて書けるので、長い条件は改行してインデントを揃えるのが慣習です。全部空、つまり「何も許可条件がない」設定はバグの可能性が高いので、`errors.New("...")` でエラーメッセージ付きのerror値を作って早期リターンしています。「許可リストなのに何も指定されていない」というユーザー設定ミスを早い段階で弾いている、という設計意図です。

uniqueCommits := make(map[string]struct{})
		for _, commit := range a.Commits {
			// Commits are case-insensitive.
			uniqueCommits[strings.TrimSpace(strings.ToLower(commit))] = struct{}{}
		}

`map[string]struct{}` はキーがstring、値が空の構造体 `struct{}` というmapです。`struct{}` は中身が何もない型で、メモリをほぼ消費しません。Goには集合（Set）型が標準にないため、「値は使わず、キーの有無だけ見たい」ときは慣習的にこの `map[キー型]struct{}` を集合代わりに使います。`for _, commit := range a.Commits` はスライスを先頭から順になめるループで、`_` はインデックス（0,1,2…）を受け取るが使わない、という意味の「捨てる変数」です。ループの中では `strings.ToLower` で小文字化し、`strings.TrimSpace` で前後の空白を除去してからmapのキーとして登録しています。同じコミットハッシュが大文字・小文字や空白違いで複数回書かれていても、ここで1つに正規化・重複排除されます。

a.Commits = maps.Keys(uniqueCommits)
		a.commitMap = uniqueCommits

`maps.Keys(uniqueCommits)` は `golang.org/x/exp/maps` パッケージの関数で、mapからキーだけを取り出してスライスにして返します。ここで正規化・重複排除済みのコミット一覧を `a.Commits` に書き戻し、さらに判定を高速化するために元のmapそのもの（`a.commitMap`）もフィールドに保存しています。スライス `a.Commits` は人間が読む用・ログ出力用、map `a.commitMap` は「このコミットは含まれているか？」を毎回ループせず `O(1)`（mapの検索は定数時間）で調べる用、という役割分担です。1つのデータを「表示用の形」と「高速検索用の形」の2つで持っておく、という設計判断がここに表れています。

values := maps.Keys(uniqueStopwords)
		a.StopWords = values
		a.stopwordTrie = ahocorasick.NewTrieBuilder().AddStrings(values).Build()

ここはコミットと同じ重複排除パターンをストップワード（無視したい単語）に対して行った後、さらに一歩進んでいます。`ahocorasick.NewTrieBuilder().AddStrings(values).Build()` は外部ライブラリの「メソッドチェーン」という書き方で、`NewTrieBuilder()` がビルダーオブジェクトを作り、`.AddStrings(values)` がそのビルダーに単語群を登録して（登録後のビルダー自身を返す）、`.Build()` が最終的な検索用データ構造（トライ木）を組み立てて返す、という3段階の呼び出しを1行でつなげています。Aho-Corasickはたくさんの単語を1回のテキストスキャンでまとめて検索できるアルゴリズムで、ストップワードが何百個あっても高速に「このテキストにどれか含まれているか」を調べられるようにする仕組みです。

if len(a.Paths) > 0 {
		a.pathPat = joinRegexOr(a.Paths)
	}
	if len(a.Regexes) > 0 {
		a.regexPat = joinRegexOr(a.Regexes)
	}

`a.Paths` や `a.Regexes` はそれぞれ複数の正規表現（`*regexp.Regexp` のスライス）です。`joinRegexOr` は同じファイル内の別の関数で、複数の正規表現を `(パターン1)|(パターン2)|...` のようなOR条件の1本の正規表現にまとめていると考えられます（この関数自体は今回の引用範囲外です）。これにより、後で実際にパス文字列や秘密情報の文字列をチェックするときに、正規表現を1つずつ順番に試す代わりに、まとめた1本の正規表現に対して1回マッチさせるだけで済みます。設定が増えてもチェック処理の呼び出し回数が増えない、という性能面の工夫です。

a.validated = true
	return nil

最後に `a.validated` を `true` にしてから `nil` を返します。これで次回以降このメソッドが呼ばれても、冒頭の `if a.validated { return nil }` に引っかかって、ここまでの重複排除やトライ木構築が二度と実行されなくなります。「最初に呼ばれたときだけ重い変換処理を行い、結果をフィールドにキャッシュしておく」という遅延初期化（lazy initialization）のパターンです。

今日覚えて帰ること

「一度だけ実行したい重い初期化処理」はbool型フラグ（例: validated）で冒頭をガードし、「値は要らずキーの有無だけ知りたい集合」はmap[キー型]struct{}で表現する——この2つのGoイディオムは、今日から自分のコードでそのまま真似できます。
