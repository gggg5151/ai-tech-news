gin-gonic/gin の auth.go を読む

GitHub で実物を見る ↗2026.10.24

GinはGo製の高速Webフレームワークで、スター数9万近い定番ライブラリです。今日はauth.goを読みます。これはBasic認証（ユーザー名とパスワードをリクエストヘッダーに載せる、一番シンプルな認証方式）を実装しているミドルウェアで、「安全な文字列比較」と「Ginのミドルウェアを作る型」という、1年目が実務で必ず出会う2つのパターンが詰まっています。auth.go、utils.go、mode.goを実際に取得して読んだ上で、この一塊を選びました。

コード

type authPair struct {
	value string
	user  string
}

type authPairs []authPair

func (a authPairs) searchCredential(authValue string) (string, bool) {
	if authValue == "" {
		return "", false
	}
	for _, pair := range a {
		if subtle.ConstantTimeCompare(bytesconv.StringToBytes(pair.value), bytesconv.StringToBytes(authValue)) == 1 {
			return pair.user, true
		}
	}
	return "", false
}

// BasicAuthForRealm returns a Basic HTTP Authorization middleware. It takes as arguments a map[string]string where
// the key is the user name and the value is the password, as well as the name of the Realm.
// If the realm is empty, "Authorization Required" will be used by default.
// (see http://tools.ietf.org/html/rfc2617#section-1.2)
func BasicAuthForRealm(accounts Accounts, realm string) HandlerFunc {
	if realm == "" {
		realm = "Authorization Required"
	}
	realm = "Basic realm=" + strconv.Quote(realm)
	pairs := processAccounts(accounts)
	return func(c *Context) {
		// Search user in the slice of allowed credentials
		user, found := pairs.searchCredential(c.requestHeader("Authorization"))
		if !found {
			// Credentials doesn't match, we return 401 and abort handlers chain.
			c.Header("WWW-Authenticate", realm)
			c.AbortWithStatus(http.StatusUnauthorized)
			return
		}

		// The user credentials was found, set user's id to key AuthUserKey in this context, the user's id can be read later using
		// c.MustGet(gin.AuthUserKey).
		c.Set(AuthUserKey, user)
	}
}

引用はリポジトリの実物と機械で照合しています。「// …略…」は省略した行です。

上から順に読む

type authPair struct {
	value string
	user  string
}

structはGoの「構造体」。複数の値を1つの型にまとめる仕組みで、TypeScriptのinterfaceやCのstructに近いです。ここではvalue（"Basic "+base64文字列、つまりAuthorizationヘッダーに来るはずの正解の値）と、そのペアに対応するuser名の2つのstring型フィールドを持つ型authPairを定義しています。フィールド名の後に型を書くのがGoの書き方で、JSONのように{}の中にkey: valueを書くのではなく、宣言の形で書く点に注意してください。

type authPairs []authPair

[]authPairは「authPair型の要素を持つスライス（可変長配列）」です。これに authPairs という名前を付けています。Goでは既存の型（ここではスライス）に別名を付けて新しい型として扱うことができ、これを『名前付き型』と呼びます。単なるタイプエイリアスではなく独立した型なので、この型にだけ専用のメソッド（次の項目）を持たせられるのがポイントです。

func (a authPairs) searchCredential(authValue string) (string, bool) {

Goにはクラスがなく、代わりに「関数の前にレシーバを書く」ことで、特定の型にメソッドを紐づけます。(a authPairs) の部分がレシーバで、「authPairs型の値aに対してこのメソッドを呼べる」という意味です。呼び出し側は pairs.searchCredential(...) のように、変数の後にドットでつなげて呼びます。戻り値が (string, bool) と2つ並んでいるのもGoの特徴で、1つ目が見つかったuser名、2つ目が「見つかったかどうか」のbool値です。Goには例外機構がなく、こうして戻り値のbool（またはerror）で成功・失敗を伝えるのが定番パターンです。

if authValue == "" {
		return "", false
	}

入力のauthValue（Authorizationヘッダーの生の文字列）が空文字なら、即座に user="", found=false を返して処理を打ち切っています。こうした『まず異常系をチェックして早期returnする』書き方はGoでは非常に頻出で、if文の中にネストを増やさずに関数の見通しを良くするための習慣です。

for _, pair := range a {

for ... range はスライスやmapを1つずつ順に取り出すループです。range a は authPairs型のスライスaの各要素を返しますが、本来は (インデックス, 要素) のペアが返ってくるところを、インデックスの方を _ （ブランク識別子、「受け取るけど使わない」という意味の特別な変数名）で捨てて、要素だけをpairという変数で受け取っています。インデックスを使わないのにエラーにならないのはこの_のおかげです。

if subtle.ConstantTimeCompare(bytesconv.StringToBytes(pair.value), bytesconv.StringToBytes(authValue)) == 1 {

ここが認証の核心です。普通ならpair.value == authValueと書きたくなりますが、Goの文字列比較は先頭から1文字ずつ順に比較して最初に違う文字が見つかった時点で処理を終えるため、「正解に近い文字列ほど比較に時間がかかる」というわずかな時間差が生まれ、攻撃者がその時間差を測ってパスワードを1文字ずつ当てられてしまう危険があります（タイミング攻撃）。subtle.ConstantTimeCompareは、結果に関係なく常に同じ時間で比較を終える関数で、戻り値はboolではなくint（一致なら1）です。bytesconv.StringToBytesは文字列をバイト列[]byteに変換するGinの内部ユーティリティで、この比較関数がstringではなく[]byteを引数に取るために必要な変換です。

return pair.user, true
		}
	}
	return "", false

一致するペアが見つかった時点でそのuser名とtrueを返して関数を抜けます（returnは即座に関数全体を終了させます）。forループを最後まで回しても一致しなかった場合は、ループの外側で最終的に "", false を返します。全部見てから結論を出す、という流れです。

func BasicAuthForRealm(accounts Accounts, realm string) HandlerFunc {

この関数は「関数を返す関数」です。戻り値の型HandlerFuncは（このファイルの外で定義されている）Ginのミドルウェア用の関数型で、だいたいfunc(*Context)のような形をしています。つまりBasicAuthForRealmは『設定（ユーザー一覧とレルム名）を受け取って、実際にリクエストごとに動くミドルウェア関数を作って返す工場』のような役割です。router.Use(gin.BasicAuthForRealm(accounts, ""))のように、ルーティング設定時に1回だけ呼ばれます。

if realm == "" {
		realm = "Authorization Required"
	}

引数realmが空文字（呼び出し側が指定しなかった場合）なら、デフォルト値"Authorization Required"を代わりに使います。Goには引数のデフォルト値を宣言時に書く機能が無いため、関数の先頭でこうして『空だったら上書きする』というガード文を書くのが定番のやり方です。

realm = "Basic realm=" + strconv.Quote(realm)

文字列の+は連結です。strconv.Quote(realm)は、realmの文字列をダブルクォートで囲み、中に特殊文字があればエスケープした安全な文字列を返します（例: Authorization Required → "Authorization Required"）。これはHTTPのWWW-Authenticateヘッダーの仕様（Basic realm="..."という形式）に沿った正しい値を作るためです。こうして作った文字列を、元のローカル変数realmに再代入して使い回しています。

pairs := processAccounts(accounts)

:=は型を明示せずに変数を宣言して代入する記法で、右辺の戻り値の型から自動的に型が決まります（型推論）。重要なのは『この行がBasicAuthForRealm呼び出し時に1回だけ実行される』という点です。processAccountsはAccounts（map[string]string、ユーザー名→パスワードの辞書）を受け取り、各組をBasicヘッダー形式の文字列に変換したauthPairsを作ります。これをリクエストが来るたびにやり直すと無駄なので、ミドルウェアのセットアップ時に前もって計算しておく、という設計判断です。

return func(c *Context) {

ここでBasicAuthForRealmの本体の戻り値である『実際のミドルウェア関数』を定義して返しています。この内側のfunc(c *Context){...}は、外側の関数のローカル変数であるpairsとrealmを自分の中で使い続けられます（これを『クロージャ』と呼びます）。*Contextの*はポインタを表し、Contextという構造体の実体そのものではなく、それがメモリ上のどこにあるかを指す「住所」を受け取るという意味です。Ginはリクエストが来るたびにこの内側の関数をそのContextを渡して呼び出します。

c.Header("WWW-Authenticate", realm)
			c.AbortWithStatus(http.StatusUnauthorized)
			return

認証に失敗した場合の処理です。c.Header(...)でレスポンスにWWW-Authenticateヘッダーをセットし、c.AbortWithStatus(http.StatusUnauthorized)でステータスコード401を設定した上で、Ginに『この後に続くはずだった他のミドルウェアやハンドラは実行しないでくれ』と伝えます（Abortは中断の意味）。最後のreturnでこの内側の関数自体を終了させ、下のc.Set(...)には到達しません。

c.Set(AuthUserKey, user)

認証に成功した場合だけ実行される行です。c.Setは、そのリクエスト専用のContextに任意のキーと値を保存する機能で、ここではAuthUserKey（ファイル冒頭で定義されている"user"という文字列の定数）をキーに、認証されたユーザー名を保存しています。これにより、この後に実行される別のハンドラがc.MustGet(gin.AuthUserKey)で『今どのユーザーとして認証されたか』を取り出せるようになります。ミドルウェア間で情報を受け渡す、Ginの基本的な作法です。

今日覚えて帰ること

「設定を受け取る外側の関数」と「リクエストごとに動く内側の関数（クロージャ）」を分け、重い処理（ここではprocessAccountsによる前計算）は外側で1回だけ行う——これがGinのミドルウェアを書くときの基本形です。func Something(config) HandlerFunc { 準備処理; return func(c *Context) { 毎回の処理 } } という形を覚えておくと、自分でミドルウェアを書くときにそのまま使えます。
