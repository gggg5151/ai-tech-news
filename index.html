「考えない」AI「Jev」登場、応答はLLMの40〜200倍速く出力無料

報道zenn.dev

サンフランシスコの企業TypeSafe AIが2026年9月15日、「System One モデル」と呼ぶAI「Jev」を公開しました。従来のLLMのように文章を生成するのではなく、事前に定義した選択肢の中から判断（choice/score/yes-no確率）だけを確率・確信度付きで返す仕組みです。TypeSafe AIのCEOはDiogo Almeida氏で、RLHF（人間のフィードバックを用いた強化学習）とInstructGPTの共同発明者とされています。

最大の売りは応答速度と低コストです。応答時間はエンドツーエンドで70〜500ミリ秒と、従来型LLMの3〜329秒に比べ40〜200倍速いとされ、日本からの実測でも往復200〜700msが確認されています。入力トークンは100万あたり0.042ドル、出力トークンは無料で、Claude Fable 5.1比238分の1のコストとされます。入力はstateとquestionsの2要素で構成され、質問形式はChoice、Score、Noulの3種類。出力はchoice、probabilities、confidenceの数値のみで文章は含みません。

一方で限界も明確です。「文章、コード、理由の説明を書くのは不可」と説明されており、計算や日付比較、複数判断が混在するタスクにも使えません。無関係な情報が多い入力では精度が低下し、学習の主言語が英語であるため日本語での確信度は英語より大幅に低下する場合があるとのことです。構造上「ハルシネーション（AIが事実に基づかない内容を生成する現象）0%」を謳いますが、選択肢の中で誤答する可能性自体は残るため、confidence値の確認が必要と説明されています。営業メールの仕分けなど、定型的な判断業務向けに位置付けられています。

Pages→App Router移行、3つの選択パターン

体験談zenn.dev

Pages RouterからApp Routerへの移行戦略について、REST API構成のプロジェクトを対象に3つの移行パターンを提示する記事です。著者は個人開発でApp Router+REST+TanStack Queryの構成を実装した経験があり、その経験から逆算してパターンを分類しています。「3か所に散った取得をどこへ寄せ直すか、という作業」が移行の本質だと述べています。

パターン1はルーティングとレイアウトのみを移行し、データ取得方法は変更しない構成。パターン2は読み取り処理をRSC（React Server Components、サーバー側でレンダリングされるReactコンポーネント）へ移行しつつ、操作の多い画面ではTanStack Query（Reactのデータ取得・キャッシュ管理ライブラリ）を残す構成。パターン3はクライアントキャッシュを完全に廃止し、書き込み処理をServer Actions（サーバー側で実行される関数を直接呼び出す仕組み）で行う構成です。判断基準として、初回訪問時の表示価値、操作を継続する画面の数、書き換えが必要なコード量の3点を挙げています。

Vercel、Goサーバーのゼロコンフィグ対応で無料デプロイが簡単に

体験談zenn.dev

Vercelの無料枠超過でVPSへ、Netlify・Cloudflare Workersは見送り

体験談zenn.dev

著者ピータン氏は、自身運営の車中泊スポット検索アプリ「車旅のしおり」（Next.js製、車中泊スポット約2,000件掲載、AdSense・Amazonアソシエイト広告あり）のホスティングをVercel Hobbyプランから移行した体験を公開しました。きっかけは、Function Invocations（関数呼び出し数）が無料枠の10万回を超過し、Fluid Active CPU（実際にCPUが稼働した時間に基づく課金指標）も月によって150%程度超過したこと、さらに広告掲載がHobbyプランの「non-commercial使用のみ」という規約に抵触する懸念があったことです。

代替候補としてCloudflare Workers、Netlify、自宅ミニPCを検証しましたが、いずれも見送っています。Cloudflare WorkersはグローバルスコープのDB接続プール再利用が並列リクエストで機能不全となり、12件同時アクセスで10件が500エラーになったこと、Netlifyは応答が4〜5倍遅延しリージョン選択に有料プランが必要なこと、自宅ミニPCは初期費用約7万円で損益分岐点が約4年になり停止・侵害リスクもあることが理由です。最終的にVPS（ConoHa、4GB/4vCPU、月2,189円）に移行しました。

移行前には詳細ページをISR（Incremental Static Regeneration、静的ページを定期的に再生成する仕組み）化してrevalidate=86400を設定し、トップページのクエリを1時間キャッシュするなど、アプリ側の最適化も実施しています。移行過程では、キャッシュヒット時にAPIキー検証がスキップされる問題や、環境変数変更後もビルドキャッシュが再利用される問題、VERCEL_ENVに依存したSentry設定が無効化される問題など複数の落とし穴に遭遇したとのことです。

移行後、東京からの応答時間（中央値）はトップページでVercelの192msからVPSの61msに改善しました。最終構成は「利用者→Cloudflare→Cloudflare Tunnel→VPS Docker→MongoDB Atlas」で、SSH接続のみポートを許可しHTTP/HTTPSは非公開、systemdタイマーで2分ごとにヘルスチェックを行う体制にしたとしています。

Codex使うなら権限プロファイルとRulesを分けて設計を

報道syu-m-5151.hatenablog.com

OpenAIのCodex（CLIツール）を使う際、確認プロンプトの多さだけで設定を判断せず、「権限プロファイル」（何を実行してよいか）と「Rules」（どの範囲なら任せるか）を分けて設計すべきだ、という実践解説記事です。筆者はClaude Codeからの移行経験を踏まえて執筆しています。

Codexには組み込みの権限プロファイルとして「:read-only」「:workspace」「:danger-full-access」の3種があり、Rulesの判定値は「allow」「prompt」「forbidden」の3種類です。CLIコマンドcodex execpolicy checkを使うと、引数列がルールにどう判定されるかを事前に確認できます。設定network_proxy = trueを有効にして初めてドメインルールが機能する点にも注意が必要です。

「承認を求めなくなっても、実行できることが増えるとは限りません。approval_policy = "never"は、確認のために止まらない設定です。アクセスできないファイルや通信先まで、自動的に開放されるわけではありません」と筆者は指摘しています。

git diffから関連テストだけ抽出するCLI「jev-test-filter」

体験談zenn.dev

mizchi氏が、今日話題のAI「Jev」を応用したCLIツール「jev-test-filter」を公開しました。git diffの変更内容から実際に影響を受ける可能性の高いテストだけを自動抽出し、vitest、jest、node:test、Playwright、cargo test、go testなど各種テストランナーが解釈できるフィルタ引数として出力します。precommit hook（コミット直前に自動実行される仕組み）での活用を想定しています。

背景にあるのは、Jevが「1つのstateに対して複数の質問を1リクエストで投げられる」という特性です。これをgit diff（state）とテスト群（質問群）の組み合わせに応用しました。使用例はjev-test-filter --base main --exec -- vitest runという一行です。Playwrightプロジェクトでの実例では、割引計算関数の変更に対し7件中1件の関連テストを正しく選別できたとしています。110件のテストを1リクエストで処理してもコストは約0.15円、実行時間は1.3秒だったと報告されています。
