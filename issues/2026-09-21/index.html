「Jev」始動、文章を書かないAI

報道itmedia.co.jp

元OpenAI研究者のディオゴ・アルメイダ氏が開発した「Jev」というAIが話題になっています。ChatGPTのような文章生成AIとは異なり、あらかじめ定義した質問や選択肢に対して構造化データ(JSON形式)で判断だけを返す「意思決定特化型AI」です。開発陣は「“スマートなif文”と考えてみて」と説明しており、発表時のX投稿がバズったことで注目を集めました。

Jevが対応する入力タイプは3種類です。複数の選択肢から1つを選ぶ「Choice」、指定範囲の数値を返す「Score」、はい/いいえの確率を返す「Noul」があり、各出力には確率と確信度が付与されます。確信度がいくつ以上なら処理を進める、といった条件分岐が可能だとされ、これが「if文」という表現につながっています。

速度とコストの主張も強気です。比較表ではGPT-6 Astraなどのフロンティア級の大規模言語モデルの応答時間が数秒〜数分とされる一方、Jevは70〜500ミリ秒、出力単価は実質ゼロコストとされています。開発側は自社評価として「193.6倍速く、444.6倍安い」と主張しています。なお、アルメイダ氏はChatGPTの前身「InstructGPT」論文の共著者の一人です。

App RouterとRSCで築く高パフォーマンス設計

報道zenn.dev

Next.js 13以降で導入された「App Router」は、React Server Components(RSC、サーバー側でレンダリングされるコンポーネント)をデフォルトのコンポーネントタイプとして採用しています。RSCはクライアント側のJavaScriptバンドルサイズに影響を与えないため、「パフォーマンス最適化の最大の鍵」になると解説されています。サーバー側で直接データベースやAPIからデータを取得でき、APIキーなどの機密情報も安全に扱えます。

一方でRSCにはuseStateやuseEffectといったReact Hooks、windowやlocalStorageなどのブラウザAPIが使えないという制限もあります。設計上は「クライアント境界をできるだけ下位にプッシュすることで、クライアントに送信されるJavaScriptの量を最小限に抑える」ことが重要だと紹介されています。

キャッシング機構についても整理されています。同じfetchリクエストが複数回呼び出されても一度だけ実行される「Request Memoization」、指定秒数キャッシュした後に再検証するrevalidateオプション、そしてrevalidatePathやrevalidateTagによるオンデマンドの再検証が組み合わさることで、高パフォーマンスな設計が実現できるとまとめられています。

16年物のSQLiteバグ、Tailscaleが特定

報道gigazine.net

2025年8月頃、Tailscaleは自社サービスでデータベース破損を報告し、その後半年間で19件の破損インシデントが発生しました。原因究明の手がかりとなったのは、同社が導入していた独自のトランザクションログパイプラインです。デバッグのために「tmstmpvfs shim」というVFSシムを追加してログを取った結果、SQLiteのWAL(ログ先行書き込み)のリセット処理中に発生する、稀なデータ競合バグが見つかりました。

バグの正体は、チェックポイント処理中に書き込みトランザクションが発生すると、チェックポイントがWALから実際より多くのページをコピーしてしまい、コミット済みのデータが後続のトランザクションから見えなくなるというものでした。この不具合は、少なくとも16年間SQLiteに潜在していたと推定されています。

Tailscaleはプロフェッショナルサポート契約のもとSQLite開発チームと共同調査を進め、修正はSQLite 3.51.3でリリースされました。最終的にSQLite 3.53.0ですべての問題が解決し、修正後4ヶ月間インシデントは発生していないといいます。地道なログ収集の積み重ねが、長年見過ごされてきた稀有な競合状態の発見につながった事例です。

Claude CodeのAGENTS.md、初回セッションは未読み込み

体験談qiita.com

Claude Code 2.1.277のchangelogには「CLAUDE.mdが存在しないプロジェクトでは、Claude CodeがAGENTS.mdを読む」という機能追加が記載されています。しかし既存の日本語解説記事の一部には「読まない」と書かれているものもあり、筆者(@suwa_nobu氏、株式会社JQIT所属)はこの食い違いを実測で検証しました。

検証方法は、各設定ファイル(AGENTS.md、CLAUDE.md、CLAUDE.local.md)に一意の合言葉を埋め込み、ファイル読み取りツールを全て禁止した状態でAIに「指示にある合言葉を全部挙げよ」と指示するというものです。Windows 10環境にClaude Code 2.1.277を隔離導入して試した結果、AGENTS.mdのみが存在する場合はその内容が読まれる一方、CLAUDE.mdやCLAUDE.local.mdが存在するとそちらが優先され、AGENTS.mdは読まれないことが分かりました。

さらに公式情報として、AGENTS.mdサポートを含むバージョンへのインストール・アップグレード後の最初のセッションではAGENTS.mdは読まれず、次のセッションから読まれるという制約があることも判明しました。CLAUDE.local.mdを個人用の未コミット指示として置くプロジェクトでは、AGENTS.mdが警告なく無効化されてしまう「落とし穴」がある点も指摘されています。

自作CLI「jsonize」、JSONをUnixパイプラインの共通言語化

体験談debimate.jp

開発者nao1215氏が、自作のCLIツール「jsonize」(コマンド名jz)を自身のブログで紹介しています。jzはコマンド出力・ファイル・引数をJSON形式に変換するツールで、270種類・737通りの出力形式に自動対応します。--extractや--excludeオプションで必要な項目を選別できるほか、CSV・TSV・YAMLなどのファイルを読み込んでJSON出力したり、newコマンドで引数からJSONを組み立てたりすることもできます。

Claude Code連携、JevでコードレビューするPlugin

体験談zenn.dev

筆者のYusuke Kikuta(muse)氏が、Claude CodeのStop hook(作業完了時に発火する仕組み)に組み込んで使うプラグイン「jev-preflight」を開発しました。作業完了のタイミングでコード差分をJev APIに送って評価させ、セキュリティリスクが検出された場合のみ再調査を促す仕組みです。評価は「behavior regression」「authorization」「input validation」など8つのリスク軸で行われますが、Jev自身がバグを断定したり自動修正したりすることはなく、やるのは「もう一度だけ調べて」と促すところまでだといいます。

技術的な工夫として、EditイベントではなくStop時点で評価することで、Write操作やシェルコマンド経由の変更も含めた完全なターン差分を確認できる点、ユーザーの既存変更とClaudeの変更を分離するため実リポジトリに書き込まない別領域(プライベートGit tree)で差分を計算する点が挙げられています。Go言語採用によりmacOS/Linux/Windowsの計6環境へ単一バイナリで配布でき、API障害時も開発を止めないfail-open設計になっています。

利用にはClaude Code 2.1.257以降、Git、Bash、TypeSafe APIキーが必要です。既定の閾値0.85は未キャリブレーションで誤検知もあり得るとされており、セキュリティゲートではなく「終了前の振り返り支援ツール」として位置づけられています。

「Jev」対抗、非自己回帰型モデル「Laya」を作った話

体験談laya.convaiinnovations.com

ConvAI Innovations創業者兼CEOのNandakishor Mukkunnoth氏が、自身が開発した非自己回帰型(non-autoregressive)の決定モデル「Laya」について解説しています。2025年3月にarXiv論文として初公開されたモデルですが、2026年9月にDiogo Almeida氏が共同創業したTypeSafe AIが「Jev」を発表したことを受け、著者はLayaを完全にリビルトしたといいます。

LayaはChoice・Score・Noulの3つの決定プリミティブを持ち、強化学習(RLCD)を用いています。単一GPUでの実行時間は32.8ミリ秒で、Jevより7.8倍高速と主張。AG Newsベンチマークでの精度はLayaが0.950、Jevが0.910、較正誤差(ECE)はLayaが0.081、Jevが0.246という数値も示されています。

100言語以上に対応し、51言語でテストしたところ45言語でランダム比3倍以上の性能を示したとのことです。一方で著者は、選択肢が20を超えると性能が低下し、Banking77では精度が0.425まで落ち込むという制限も認めています。

RSA-896の因数分解に成功、GPU2048基で10日間

著者のStephen A. Weis氏が、2026年9月19日にRSA-896(896ビットRSA鍵)の因数分解に成功したと報告しています。Claudeを使ってCADO-NFS(一般数体篩法の実装)をGPU対応に改造し、Anthropicのデータセンターで最大2048基のGPUを10日間、総計約30GPU年相当の計算資源を投じたといいます。

著者は、この結果がRSA-1024鍵はデータセンター規模のGPUリソースを持つ攻撃者に対して脆弱である可能性を示すとしつつ、GNFSアルゴリズム自体の実行時間を大きく改善したわけではないと明言しています。実運用されているRSA-2048鍵のセキュリティには影響しないとも述べており、あくまで計算資源の物量で押し切った一つの実験例として位置づけています。
