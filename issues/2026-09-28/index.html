報道publickey1.jp

Docker社は、AIエージェント向けのクラウドベースのサンドボックス環境「Docker Cloud Sandboxes」を発表しました。最大の特徴は、ローカルマシン上の「Docker Sandboxes」とクラウド上の「Docker Cloud Sandboxes」の間で、稼働中のサンドボックスを中断せずに移動できる点で、両者は同じMicroVM技術・CLIインターフェイス・トラストモデルを共有しています。

Honoが「Web標準API」だけに依存する設計である理由

報道qiita.com

記事では、自身をHonoの「エアプ」（実際に使い込んだ経験がない立場）と認める著者が、Honoが良いとされる理由を調べた内容がまとめられています。結論として、HonoはRequest/ResponseというWeb標準APIのみに依存し、Node.js固有のAPIを使わない設計になっているため、複数のJavaScriptランタイム環境で動作できる点が強みだとされています。

Next.jsのServer Actionは「関数」ではなく公開エンドポイントだった

報道zenn.dev

Next.jsのServer Actionsは一見「関数」のように書けますが、実装上はビルド時にIDが割り振られ、POSTリクエストでアクセス可能な公開HTTPエンドポイントになるという技術的な注意点を解説する記事です。「'use server'」とマークされたファイル内でexportした関数は、権限チェックがなければ誰でも呼び出せてしまう可能性があると指摘されています。

もう一つの落とし穴として、ビルドが変わるとServer ActionのIDも変動するため、古いビルドを参照したままのタブから「Server Action "..." was not found on the server」というエラーが発生する現象が紹介されています。対策として、認証が必要な関数はexportせず、同一ファイル内の別のexportされたアクション経由でのみ呼び出す方法や、grep -rn "^export async function" srcで公開されている関数を把握する方法が挙げられています。筆者は「同じ見た目のコードが、まったく違うものになっている」と述べ、注意を促しています。

Echo v4→v5移行、作業の9割はContext型変更 自動化スクリプトも公開

報道zenn.dev

Go言語のWebフレームワークEchoのv4サポートが2026年12月31日で終了することを見据え、v4からv5への移行手順を整理した実務ガイドです。変更点は「Context型の変更」「ルーター構造の変更」「ロギング機構の変更」「起動処理の変更」の4つに整理されており、著者によれば作業量の約9割がContext型の変更に関するものだといいます。Context型はインターフェースから構造体へ変わり、ハンドラ引数はすべて*echo.Contextに統一されます。

ロギング機構は独自インターフェースからlog/slogへ移行し、InfofやFatalメソッドが削除されるため、例えばe.Logger.Infof("route: %s", p)はe.Logger.Info("route", slog.String("path", p))のように書き換える必要があります。エラーハンドラの引数順序もerrorHandler(err error, c echo.Context)からerrorHandler(c *echo.Context, err error)へ変更されます。

著者は機械的に置換できる部分を自動化するBashスクリプト「migrate-echo-v5.sh」を公開しており、GNU sedとBSD sedの自動判別や、未コミット変更がある場合の処理中断などに対応しています。一方で「コンパイルもテストも通ってしまう」落とし穴もあると注意を促しており、動作確認を怠らないよう呼びかけています。

RLVR入門、人間の採点を介さずコードやSQLの正誤で報酬を与える

報道zenn.dev

RLVR(Reinforcement Learning with Verifiable Rewards、検証可能な報酬による強化学習)を解説する記事です。人間の採点(報酬モデル)を介さず、テストの成否や最終解の正誤など機械的に判定可能な客観的正誤をそのまま報酬として用いる手法で、数学証明・コード生成・SQL実行など正誤が明確なタスクに適用されます。従来のRLHF(人間の好みを学習した報酬モデルを使う手法)には学習コストの高さや報酬ハッキングが起きうるという課題があるとされています。

報酬設計手法として、複数の回答をグループとみなしグループの平均より良かった回答の出やすさを上げるGRPO(Group Relative Policy Optimization)が紹介されています。DeepSeekMathで提案されたこの手法は、2025年初頭に公開されたDeepSeek-R1-Zeroにも採用され、正確性の報酬と形式の報酬という2種類の報酬設計が使われました。

外部事例として、MetaのSWE-RLでLlama3-SWE-RL-70BがSWE-bench Verifiedで41.0%の解決率を達成したこと、Cursorの「Composer」ではpost-trainingに投じた計算量が事前学習を上回るとされることも紹介されています。本記事はシリーズの第1回で、次回はDatabricksの事例を扱う予定とのことです。

LLMの「私」の語り方、チャットテンプレートで反転すると判明

報道arxiv.org

LLMが自分自身について語る際の「声」が、モデル固有の性質ではなくチャットテンプレート（プロンプトの整形方法）によって左右されることを示したarXiv論文です。8つのオープンソースモデルを対象にした実験で、チャットテンプレートの有無によって「私は感じる」のような経験的な声と「私はただのAIです」のような免責的な声の比率が反転することが確認されました。

さらに研究者は、モデルの活性化空間内にこの「声」を操作できる方向(ベクトル)が存在することを発見し、この方向を用いた活性化ステアリングによって、チャットテンプレートによる声の変化と同様の効果を人工的に再現できることも示しました。研究は、LLMの自己言及の内容がモデル固有の特性ではなく展開方法に部分的に依存していると結論づけています。
