Cloudflare、分類特化の決定モデル「Clef」公開

体験談blog.cloudflare.com

Cloudflareが自社ブログで、「Clef」という決定モデル（Decision Model）の公開を報告しています。通常のテキスト生成ではなく、顧客サポートメッセージの緊急度判定や対応すべきチームの振り分けといった分類タスクに特化し、構造化された出力と確率を返すモデルです。テキストに加え画像分類（ビジョン）にも対応し、64kのコンテキストウィンドウを持ちます。

ベースモデルにはQwenを採用し、通常のLLMのように1トークンずつ生成するのではなく、非自己回帰的な決定ステップを用いることで高速化を図っています。中央値レイテンシはClefが209.3ms、軽量版の「Clef-flash」は38.8msとされています。

ClefはApache 2.0ライセンスのもとHugging Faceで公開されており、ローカル実行も可能です。あわせてCloudflare Workers AIでもホスティングされ、既存の互換APIと互換性を保っています。強化学習によるClefの微調整サービスも提供が開始されました。発表は2026年10月1日です。

Google、出力100万トークンの新モデル「Gemini 4 Argon」発表

報道techno-edge.net

Googleが新フロンティアモデル「Gemini 4 Argon」を発表しました。最大の特徴は出力上限100万トークンで、Claude Opus 5.5やGPT-6 Astraの12万8000トークンの約8倍にあたります。Googleは「複雑かつ長期的なワークフロー全体にわたって深い推論を持続」するよう構築したと説明しており、社内では数千人が日常業務で使用しているといいます。

ベンチマークでは他モデルを大きく上回りました。業務自動化系のAutomationBenchはArgon 51.3%に対しOpus 5.5が42.5%、Astraが41.4%。法務系のHarvey's Legal AgentはArgon 19.6%に対しOpus 5.5が3.8%、Astraが5.4%。金融系のVals Finance Agent v2はArgon 65.4%に対しOpus 5.5が58.6%、Astraが53.5%。長文脈のGraphWalks（256k〜100万）はArgon 84.2%に対しOpus 5.5が66.8%、Astraが71.8%でした。

実務応用例として、データセンターのメモリ最適化で500TiB〜1PiBの節約が見込める成果を示したほか、動画再生ライブラリの3万2000行のC++コードをRustに書き換える作業にも使われたとしています。

提供は「Fairwind Program」を通じて審査済みのサイバー防御組織から開始され、その後有料APIユーザーとGoogle AI Ultraユーザーへ段階的に拡大される予定です。価格は入力が100万トークンあたり2ドル、出力が10ドルで、キャッシュ済み入力は95%引きとなります。

DeepMind、AI生成タンパク質に見えない透かし「SynthID Bio」

報道gigazine.net

Google DeepMindが2026年9月30日、AIが設計したタンパク質に「見えない透かし」を埋め込む技術「SynthID Bio」を発表しました。アミノ酸配列の生成時に、タンパク質の性質を大きく変えない範囲でアミノ酸の選択をわずかに誘導し、統計的に検出可能な特徴を埋め込む仕組みで、立体構造データには原子座標の微調整という別手法を使います。透かし入りタンパク質は透かしなしと同程度の設計成功率・結合強度を保ち、デジタルデータだけでなく実際に合成したタンパク質からも透かしを検出できるのが特徴です。

VEGF-A、SARS-CoV-2スパイクタンパク質RBD、PD-L1という3種の標的タンパク質で検証され、AlphaFold 3やゲノム生成AI「Evo 2」にも統合済みです。DNA合成時のスクリーニングや、Protein Data Bank・UniProt・GenBankなどの生物学データベースでAI生成データを識別する用途が想定されています。

OpenAI、1万5000人規模の組織的「蒸留攻撃」を阻止と報告

報道gigazine.net

OpenAIが「1万5000人以上のユーザーによる組織化された敵対的蒸留攻撃」を検出・阻止したと報告しました。蒸留攻撃とは、高性能モデルの応答内容を取り込んで別のモデルの性能を高める手法のことです。OpenAIは攻撃の中心人物について、Kimiシリーズの開発元である中国企業Moonshot AIに関係する人物だと推測しています。

攻撃は2026年7月1日に開始され、7月24〜25日には関与ユーザー数が4000人以上に急増（同期間のリクエスト数は1万6000件）、総ユーザー数は1万5000人以上に達しました。OpenAIは7月28日に攻撃を阻止しています。

手法は、高性能モデルの思考内容を同一企業の低性能モデルに読み込ませ、その低性能モデルに脱獄攻撃を仕掛けることで思考内容を平文で出力させるというもので、OpenAIが暗号化している思考プロセスを迂回するものでした。OpenAIは対策を強化し、業界団体Frontier Model Forumを通じて他のAI企業への情報共有も行ったとしています。

AI文章を構造から直すClaude Skill「yomiyasu」

体験談zenn.dev

AI生成テキスト特有の不自然さ（いわゆる「AI-Slop」）を、禁止語句のブラックリストではなく統語構造の復元と比喩動詞の具体化レベルで改善するAgent Skill「yomiyasu（よみやす）」が作者自身によって公開されました。Claude Code、Codex、Cursorなどに対応し、「npx skills add nanaism/yomiyasu」で導入できます。ライセンスはMITです。

useLinkStatusで遷移中フィードバックを実装

体験談zenn.dev

筆者が個人開発する日程調整・集金アプリ「いいカンジ」で、参加者ページから幹事ページ（/e/[editToken]という動的ルートでSupabaseからデータ取得）へのリンクをタップした際に画面が固まって見える問題を解決した記録です。以前設置していたloading.tsxはバックグラウンドタブで開くとスケルトン表示が止まる不具合があり削除しましたが、通信が遅い環境では画面切り替えが遅延するトレードオフが生じました。

解決策としてNext.jsのuseLinkStatusフックを使い、遷移の保留状態をpendingという真偽値で取得。ボタンラベルを別コンポーネントに分離し、保留中は「開いています…」とスピナー表示に切り替えました。useLinkStatusは<Link>の子孫コンポーネントでのみ機能する点に注意が必要だとしています。

prefetchが有効だとpending状態がスキップされるため、該当リンクにはprefetch={false}を明示的に設定。ラベルのdata-pending属性をTailwind CSS v4のhas-[[data-pending]]セレクタで検出し、保留中はpointer-events-noneとopacity-70を適用して連打防止を実現したとしています。

AIエージェント優先に作り変えたdotfiles

体験談tellme.tokyo

筆者は直近のコマンド実行統計でghコマンドの実行回数が人間80回に対しAI（Claude/Codexなど）が1,339回だったことに気づき、10年以上かけて人間向けに構築してきたdotfilesをAI優先に作り変えました。既存dotfilesに含まれていた「cp -i」の確認プロンプトや、入力待ちが発生する「enhancd」というツールを削除しています。

TTYと環境変数で人間かどうかを判定する「is_human」という関数を導入し、人間でないと判定された場合は.zshrcの処理を途中で抜ける設計にしたことで、AIによるシェル起動時間が0.5秒から0.01秒に短縮されました。cpなどのエイリアスは削除して確認なしで実行されるようにしつつ、「gomi」というカスタムrmコマンドをalias rm=gomiとして設定し、AIには本物のrmだと思わせつつ実際はゴミ箱機能を持つgomiを使わせる工夫も行っています。

rg、jq、yq、shellcheckなどAIが頻用するツールを先制的に導入し、Nixとhome-managerを使ってツール1つにつき1ファイルでインストールと設定を共置する管理方式を採用したとしています。

Next.js v16.3.8、SSRF含む6件の脆弱性を修正

公式github.com

Next.jsのv16.3.8がリリースされました。6件のセキュリティ脆弱性への対応を含むパッチリリースで、画像最適化機能におけるSSRF（サーバーサイドリクエストフォージェリ、意図しない宛先への通信を強制される脆弱性）が高リスクの脆弱性として修正されています。

中程度の脆弱性としては、App Routerのメタデータ画像ルートでの情報開示、自ホスト環境でのSSG/ISRキャッシュポイズニング、キャッシュ汚染による永続的なDoS、Draft Modeの内容リーク、ネストされた「use cache」関数のキャッシュリークが修正されました。低リスクとして開発サーバーのMCPエンドポイントの情報開示も修正されています。該当する環境では早めのアップデートが推奨されます。

長期の一人称視点動画を記憶するAI「MemLife」

公式arxiv.org

長期間の一人称視点（エゴセントリック）ビデオから日常生活を理解・推論するAIアシスタント向けのメモリシステム「MemLife」を提案する論文です。数百時間規模の動画をそのまま処理するのは計算コストが高すぎるため、動画内容をテキスト化してメモリとして蓄積・検索する方式を取り、「重要な証拠を保持できない」「検索空間が広がり関連情報を見つけられない」という従来手法の2つの課題解決を狙います。

エンティティ単位で一人称視点のテキストエピソードを生成する仕組みと、時間インデックスを使ったエージェント型の検索の2要素で構成され、強化学習でメモリの質を最適化する「MemOpt」も提案しています。4つの長期ベンチマークで、訓練不要の既存最強手法を4.6〜12.0%上回り、MemOptによりさらに2.7〜5.0%向上したとしています。

文脈を自ら管理する言語モデル

公式arxiv.org

言語モデル自身が「文脈」をファイルとして扱い、自律的に更新・管理する仕組みを提案する論文「Context Language Models」です。既存モデルにゼロショットで組み込むだけで複数タスクの性能が向上し、BrowseComp-Plusというタスクでは精度が11.4%向上、計算量が21.5%削減されたとしています。

自然言語指示によるチューニングで精度が最大35.9ポイント改善、強化学習を適用した場合はQwen3.5-9Bの性能が47.6%向上したとのことです。推論コストを下げる専用の最適化技術「Suffix Cache Reuse」により、サーバー側の計算コストをさらに35%削減できるとしています。

エージェントの実行基盤を自動発見する「MILO」

公式arxiv.org

エージェント用の実行制御フレームワーク（ハーネス）の設計を自動化する新手法「MILO」を提案する論文です。既存の自動化手法は探索空間が限定的という課題があったのに対し、MILOは島（island）ベースの進化的探索に階層的な系統記憶やミューテータエージェント、オーケストレータを組み合わせて探索範囲を拡大します。

複数のベンチマークで既存手法を大幅に上回る性能を示し、特にTerminal-Bench 2.1ではMILOが86.1%を記録、公式リーダーボードの最高記録83.8%を上回ったと報告しています。
