Claude Codeを自分好みに拡張できるMod機能

報道gigazine.net

Anthropicは2026年10月1日、AIコーディングエージェント「Claude Code」にカスタマイズ機能「Mod」を追加したと発表しました。TypeScriptで記述し、プラグイン機能を通じてCLI版・デスクトップ版の両方にインストールできます。Modは発生する全イベントをリアルタイムで監視でき、独自のボタンやUI描画にも対応します。

Claude Code使用量を実測、Max枠の「重み」がAPI料金表と違った

体験談zenn.dev

Claude Code Max 20xプランを契約する筆者が、ClaudeCodeとAPIの間に自作プロキシを挟み、リクエストごとのトークン数と使用率（%）のレスポンスヘッダを記録する独自の手法で、Max枠内での各トークン種別・モデルの「重み」を実測・逆算した検証レポートです。

実測の結果、トークン種別の重みはInputを1とした場合、Outputが5、Cache writeが1.25、Cache readが0.025でした。API料金表ではCache readは入力の0.025倍から0.1倍とされていますが、実測では測定した全モデルで一貫して0.025倍だったといいます。モデル別の重みはHaiku 4.5を1とすると、Sonnet 5が1.5、Opus 5.5が2.2、Opus 5が2.75、Fable 5.1が10で、Opus 5.5の重みはAPI単価比より軽く設定されていたことも分かりました。

さらに5時間枠は3億トークン相当、週間枠は11.3億トークン相当とされ、5時間枠では、headlessモードは対話モードの2倍から2.86倍の速さで使用量を消費することも判明しました。筆者は「数値はすべて、筆者が契約しているMax 20xで2026年9月に測った値で、Anthropicが公表した係数ではありません」と念を押しています。

Anthropic Batches APIで大量リクエストのコストを半減

体験談zenn.dev

5万件のレビュー分類作業でコストを気にした経験を動機に、Anthropic Message Batches APIを使って大量のLLMリクエストのコストを削減する実装手順を5ステップで解説する記事です。著者は「リアルタイム応答が不要なのに同期APIを使い続けるのは、純粋にコストの無駄」と指摘しています。

手順は、@anthropic-ai/sdkのインストールに始まり、最大10,000件まで対応するバッチリクエストの作成、ポーリングによる完了待ち（通常1時間以内、最大24時間）、AsyncIterableを活用した非同期での結果取得という流れです。Batches APIは通常のAPIと比べてコストを50%削減できるとされ、Prompt Caching（キャッシュヒット時は入力トークンが90%オフ）と組み合わせると理論上95%以上のコスト削減も可能だとしています。

Next.jsのuse cache: private、ブラウザ側に古いキャッシュが残存する落とし穴

体験談zenn.dev

Next.js v16で導入された「use cache: private」ディレクティブは、cookies()などリクエスト固有の値をキャッシュし、本来はサーバーに保存されず単一リクエスト内での再利用のみを意図したものです。しかし筆者がNext.js 16.3.8の本番モード（next build && next start）で検証したところ、特定の設定下ではこのキャッシュがブラウザのメモリに保存され、stale timeの間は複数のリクエストやページ遷移をまたいで再利用されてしまうことが分かりました。

検証では、cacheComponents設定のみの場合はキャッシュがブラウザに保存されませんが、Partial Prefetchingを有効にしかつstale timeが5分以上の場合、キャッシュがブラウザに保存され、同一パスへの再遷移時に旧キャッシュが使われてしまうことが確認されました。これにより、ログアウト後も古いユーザー固有情報が表示され続けるなど、情報漏洩につながるリスクがあると筆者は指摘しています。

対策として、Server Action経由でcookieを削除すればキャッシュは即座に消えますが、Route Handlerやクライアント側でcookieを削除した場合はキャッシュが残存するため、router.refresh()の実行で解消する必要があるとまとめています。

Where-OPD、合成シーンだけでMLLMの知覚能力を鍛える

公式arxiv.org

Incident-Arena、コーディングエージェントに本番障害対応を課す新ベンチマーク

公式arxiv.org

AIコーディングエージェントが本番環境のインシデント対応をどれだけこなせるかを評価する新ベンチマーク「Incident-Arena」を提案する論文です。既存ベンチマークはおもちゃのリポジトリや非標準フレームワーク、単純な静的検証に頼っており、現実の障害対応を測れていないと指摘し、実際の本番ソフトウェアを模したKubernetesクラスタに多層的な障害を注入し、機能面とシステムメトリクスの両面で検証するテストスイートを構築しました。
