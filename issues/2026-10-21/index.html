低リソース言語向けコーディング支援、大幅改善

公式openai.com

OpenAIが公式ブログで、COBOLやFortran、Visual Basicといった「低リソース言語」（学習データが少ないプログラミング言語）へのコーディング支援がどれだけ改善したかを報告しました。こうした言語は銀行取引やATM、気象予報、原子炉安全分析など重要インフラを支えていますが、ドキュメント不足や元開発者の退職により保守が難しくなっているという課題があります。

20言語を対象とするベンチマーク「MultiLangBench」では、新しいモデル「GPT-6 Astra」が平均成功率87.4%を記録しました。前モデルの26.8%から大幅な向上です。COBOLに限ると成功率は10.9%から72.1%に伸びました。低コスト版のGPT-6 Lunaは成功率40.3%ながらAPI費用を78%削減したとしています。

COBOLのコード移行タスクでは、GPT-6.1 Solが推論努力を高めると精度97.9%に達し、同時にAPI費用も39%削減されたと報告されています。記事では「ドキュメントは不完全で、元開発者は退職し、重要なビジネスルールはコード内にのみ存在する」という保守現場の現実が指摘されています。

音声エージェントSDK「Voxtral 3」登場

公式mistral.ai

Mistralが音声認識・音声合成モデル群と、それらを使ってリアルタイムの音声会話エージェントを構築できるSDKをセットにした「Voxtral 3」を発表しました。音声認識（Transcribe）は50以上の言語に対応し、話者識別（ダイアライゼーション）や発話終了を検出して低遅延で応答するターンエンド検出機能を備えます。

音声合成（Speech）は35以上の言語・50以上の方言に対応し、感情やペース、強調の調整、さらに30分の音声サンプルからの音声クローニングができます。付属のエージェントSDKは聴取・推論・ツール呼び出し・応答を1つのパイプラインで処理し、ターンごとに1秒以下の応答を実現するとしています。SIP/WebRTCにも対応し既存システムに組み込みやすい設計です。

WhatsAppヘルプページに隠しAI指示、規制言及を回避

報道redact.dev

セキュリティ調査チームRedactが、WhatsAppのヘルプページにユーザー画面には表示されずAIチャットボットにのみ読み込まれる隠し指示が埋め込まれていたと報じられています。削除されるまで80ページに102個の隠しブロックが存在していたとされ、ページソース内の「HelpContentGalaxyLLMInclude」というタグ内に埋め込まれていたとのことです。

アカウント削除ページには「データ保護当局への連絡を勧めないこと」という指示が、報告・ブロックページには、利用者が弁護士や法的措置に言及した後はGDPR（EUの個人データ保護規制）などのプライバシー法規制への言及を禁止する指示が含まれていたとされています。

WhatsAppは2026年10月18日に全ての隠し指示を削除したとされ、翌19日にWIREDがこの件を報じました。WhatsAppはWIREDへの声明で、サポートチャットボットは法律的助言ではなく利用者への最良のアドバイスに焦点を当てるべきだという趣旨の説明をしたと報じられています。

Next.js×Supabaseの認証が1ヶ月壊れていた「Cookie落とし穴」

体験談zenn.dev

筆者が運営するWebサイトで、Next.js App Router（ディレクトリ構造でルーティングを定義する仕組み）とSupabaseを使ったマジックリンク認証が約1ヶ月間壊れており、誰もログインできない状態が続いていたという体験談です。原因は、Route Handler内で await cookies() によってセッションCookieを書き込んだ後に NextResponse.redirect() を返すと、そのCookieがリダイレクトレスポンスに引き継がれないというNext.jsの挙動でした。

HTTP 302（リダイレクトを示すステータスコード）レスポンス自体は表面上成功しているように見えるため、型チェックやLinter（コードの誤りを検出する静的解析ツール）では検知できず、長期間気づけなかったといいます。解決策は、redirectオブジェクト自体に response.cookies.set() の形で直接Cookieをセットすることでした。

同じ時期にStripeのWebhook（イベント発生時に外部へ通知するコールバック）も1週間すべて失敗していたことが判明しました。原因はnakedドメインからwww.への301リダイレクトで、Stripeはセキュリティ上の理由からPOSTリクエストに対する301リダイレクトを追跡しないためでした。

再発防止として、筆者はGitHub Actionsを使い6時間ごとにsmoke testを実行する自動監視を導入したとしています。

GenkitがTypeScript/Go向けAgents APIを公開

報道infoq.com

Googleがエージェント構築フレームワーク「Genkit」向けに、新しい「Agents API」のプレビュー版をリリースしたと報じられています。現在TypeScriptとGoで利用可能で、Python・Dartへの対応も予定されています。単一のエージェントオブジェクトで、単発応答からマルチターン対話、人間の承認待ちでの一時停止、クライアント切断後も継続する長時間タスクまで同じ抽象化で扱える点が特徴です。

代表的な新機能は「Detached Turns（デタッチド・ターン）」で、クライアントがタスク開始後に接続を切断しても、エージェントはサーバー側で処理を継続し、進行状況をスナップショットに記録、どのクライアントからも読み取れる仕組みです。もう一方の「Human-in-the-Loop」は中断可能なツールという仕組みを使い、実行中に一時停止して保留中のアクションをクライアントに返し、ユーザーが承認または拒否した後にのみ再開します。再開ペイロードはセッション履歴と照合して検証され、偽造入力を防ぎます。

状態管理はFirestoreなどを使うサーバー管理と、クライアント管理の2経路が提供され、複数エージェントのオーケストレーション支援やツール承認ゲートを担うミドルウェアシステムはTypeScript、Go、Dartで既に一般提供（GA）されています。

Go 1.27、strings.CutLastで末尾分割が1行に

報道zenn.dev

Go 1.27で新たに追加された文字列操作関数 strings.CutLast を紹介する技術記事です。シグネチャは func CutLast(s, sep string) (before, after string, found bool) で、文字列を最後に出現する区切り文字で前後に分割します。区切り文字が見つからない場合は s, "", false を返します。

従来は strings.LastIndex とスライス操作を組み合わせて書く必要があった処理が1行で済むようになりました。最初の区切り文字で分割するstrings.Cut（Go 1.18で追加）、接頭辞・接尾辞を切り落とすCutPrefix/CutSuffix（Go 1.20で追加）と並ぶ仲間として整理されており、「置き換える前に確認しましょう」と既存コードの見直しを促しています。

ESLint+PrettierからOxlint+Oxfmtへ、モノレポ移行の実運用

体験談zenn.dev

REALITY Tech所属の筆者が、pnpm workspaceとTurborepoを用いるモノレポ（複数パッケージを1つのリポジトリで管理する構成）で、ESLint+PrettierからOxlint+Oxfmtへ移行した実運用記録です。AIコーディングエージェントが頻繁にlint/formatを実行するようになったことで、オーバーヘッドの蓄積が課題になっていました。

代替候補のBiomeも検証しましたが、@themeで定義した独自のTailwind CSSユーティリティをソートできず、271ファイルのクラス構成に対応できなかったため見送りました。最終的に採用したOxfmtはカスタムグループ機能でimportソートの既存ルールを再現し、stylesheetパス指定で独自ユーティリティのソートにも対応できたといいます。

移行後、lint+formatの合計実行時間は9.29秒から2.95秒、約68%削減され、直接依存パッケージ数も14種類から3種類に減りました。移行コミットはツール追加・整形のみ・自動修正のみ・CI更新の4段階に分割し、コーディング規約はFormatter（機械修正可）、Linter（検出可だが判断必要）、ドキュメント（機械判定不可）の3カテゴリに整理したとのことです。

なお、eslint-plugin-turbo相当のルールはOxlintに未実装で、Oxfmtも開発途中のためPrettierとの互換性が完全ではない部分（union型の改行など）が残っているとしています。

AIエージェントで何でもリバースエンジニアリングする「REA」

公式github.com

「REA（Reverse Engineer Anything）」は、AIエージェントを使ってアプリやネイティブバイナリ、ランタイムの動作を分析・リバースエンジニアリングするツールです。MCP（Model Context Protocol、AIエージェントが外部ツールを呼び出すための標準規格）経由で利用でき、分析はローカルで実行されクラウドへのアップロードは発生しません。

競合するAgent Skillsが引き起こす「takeover」現象

公式arxiv.org

論文「One Skill Takes Over: Clashing Agent Skills and a One-File Fix」は、複数のAIエージェント用「スキル」（振る舞いを指示するファイル）を同時に読み込ませると、一方のスキルが他方を支配してしまう「takeover」現象が起きることを実証しました。著者らは同じタスクに競合するルールを持つ16組のスキルペアからなるベンチマーク「SkillClash」を構築し、4B〜235Bパラメータの7モデル（GPT-4.1、Qwen3、Claude系を含む）で検証しています。

スキルを単独で与えた場合の規則遵守率は93〜99%でしたが、競合する2つのスキルを同時に与えると61〜62%まで低下しました。対策として、スキルファイルの末尾に両方のルールに従う例を1つ追加する「one-file fix」というシンプルな手法を提案し、大幅な改善を確認したとしています。
