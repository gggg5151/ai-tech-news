中国系ハッカー集団、AIエージェントで大規模侵入 ARTEX悪用

報道microsoft.com

Microsoftのセキュリティブログが、2021年から活動する中国国家支援の攻撃グループ「Storm-0940」が、オープンソースのAI駆動型ペネトレーションテスト（侵入テスト）フレームワーク「ARTEX」を使い、2026年10月に大規模なサプライチェーン攻撃を実行したと報告しました。ARTEXはGo言語で書かれたマルチエージェントLLMシステムで、英語・韓国語・中国語・スペイン語・日本語に対応し、偵察からデータ流出までを自律的に実行できるとされています。

攻撃は10月10日から14日にかけて、8組織・327アカウントを狙ったパスワードスプレー（複数アカウントに同じパスワードを一斉に試す攻撃）から始まり、15万1000件以上のログイン失敗が発生しました。10月15日以降は分当たり最大2900件というペースで2250以上のテナントへのサインインが試みられたと記されています。

侵入経路として悪用されたのは、ConnectWise関連のマルチテナント型クラウドバックアップアプリケーションの侵害済み認証情報によるOAuth（第三者アプリに権限を委譲する認可の仕組み）の不正利用です。テナント内でこれらアプリが確立していた信頼関係を踏み台にし、複数の事例で初期アクセスからグローバル管理者権限の獲得まで3時間未満だったとされています。標的は航空防衛・金融・政府・製造・テクノロジーなど多業界に及びました。Microsoftはこの活動が自社システムの脆弱性によるものではないと明言し、検出クエリや侵害指標を公開しています。

公式openai.com

これを踏まえ、検証と修正開発、対象組織への対応時間の確保、政府パートナーとの連携、各製品への更新の展開、パッチ公開後のガイダンス公表という5段階からなる協調対応フレームワークを提案しています。少人数チームで運営されることが多いソフトウェアメンテナーに向けて、資金・高性能モデルへのアクセス・実務的なエンジニアリング支援を提供するとしており、具体的には「Daybreak」への補助付きアクセスとして10億ドルを投じることを約束しています。

LLMに「自信度」を聞いても意味がない、という指摘

報道rumple.github.io

LLM（大規模言語モデル）に「この答えにどれくらい自信があるか」を数値で尋ねる「信頼度スコア（confidence scoring）」は危険だ、と主張する記事です。LLMは根拠に基づいて確率を計算しているのではなく、通常の文章生成と同じ仕組みでトークン（文章を構成する単位）を1つずつ予測しながら「自信度っぽい数字」を書いているだけであり、その数字は実際の正確さや情報量を反映しないと論じています。

記事によれば、同じ質問でもLLMに信頼度を尋ねると答えが変わることがあり、質問の言い回しを変えるだけでも数値が変動するといいます。ある数値が信頼度スコアとして機能するには、(1)予測の根拠となる実際の情報量を反映していること、(2)同種の問題で実際の結果と照合（キャリブレーション）されていること、の2条件が必要だが、LLMの出力はどちらも満たしていないと結論づけています。

"The model writes it, token by token, in the same way that it writes any other text."という一文が、この主張の核心を端的に表しています。

Next.js×Supabase Authのリダイレクトループ、原因3パターン

体験談zenn.dev

Next.js + Supabase Auth構成でmiddleware（リクエストの前処理を行う仕組み）による認証チェックを実装した際に遭遇したリダイレクトループの原因を、筆者（Webアプリケーションエンジニア）が3パターンに分けて解説しています。

1つ目はクッキー書き込み処理（setAll）の実装が空になっているケースです。Supabase AuthはクッキーのやりとりでJWT（認証情報を含むトークン形式）のリフレッシュを行っているため、setAllが空だとレスポンスにクッキーが反映されず、次のリクエストでgetUser()がnullを返し続けます。2つ目はmiddlewareのmatcher設定に/auth/callbackを含めてしまい、OAuthコールバック処理が実行されずログイン画面へのリダイレクトが繰り返されるケース。3つ目はNext.js 15以降で非同期になったcookies()にawaitを付け忘れ、セッションチェックが常にnullを返すケースです。

記事では、適切なクッキー管理を行うmiddleware.tsの完全なコード例、認証関連ルートを除外するmatcherパターン、デバッグ用のconsole.log記述例が示されています。

コードベースを知識グラフ化する「Graphify」

LLMの長期記憶、侵害が持続する新たな脆弱性

公式arxiv.org

LLMの「長期記憶」機能を悪用した新たなセキュリティ脆弱性「メモリインジェクション」に関する研究です。従来のチャットボットでは攻撃の影響がセッション内に限定されていましたが、長期記憶を持つ現代のLLMインターフェースではこの制限がなくなり、攻撃が持続的な侵害につながることを示しています。

ChatGPT Instant 5.3、Claude Sonnet 4.6、Gemini 3 Flashの3サービスを対象に実際に攻撃を検証し、個人のメモリ、プロジェクト、スキル、組織の指示、MCP接続リソースなど複数の経路から攻撃が可能であること、評価したNISTの攻撃目標がいずれかのサービスで達成可能であることを報告しています。特にClaudeの共有メモリ機能を使うと、組織内の複数ユーザーを侵害したりプロンプトを漏洩させたりできるとされています。評価した防御メカニズムのおよそ半数が実装されていなかったとも述べられています。

コーディングエージェント、バックアップ実行率はわずか15%

公式arxiv.org

コーディングエージェントは、ファイルやデータベースなどの状態を変更する操作を行う際、後で元に戻す必要が生じる可能性を予見してバックアップを取る能力（バックアップ認識）が低いことを指摘する研究です。著者らはこれを測るベンチマーク「RegretBench」（205の実行可能タスク）を構築しました。

6つのフロンティアモデルを評価したところ、タスク完了率は86.1%だった一方、バックアップ実行率はわずか15.2%にとどまりました。これを解決するため、ツール呼び出しを監視し状態変更前にバックアップを取るプラグイン型レイヤー「BackUpper」を提案。平均92.2%の類似度で状態復元を実現し、コストはタスクあたり0.014ドル、メインエージェントが自己バックアップする場合と比べてトークン使用量も7倍少なかったとしています。
